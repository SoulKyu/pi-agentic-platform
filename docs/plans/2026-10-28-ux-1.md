# UX-1: links, terminal hand-off, quotes, context meter, prompt templates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the friction between the chat and the code: file paths in replies open Files at the line, shell blocks go to the session's terminal without running, a selection can be quoted into the composer, the composer shows context and cost, and one of your messages can be saved as a Pi prompt template.

**Architecture:**
- **Daemon, two changes only (spec §4):** a `cost` figure on the session stream (snapshot field and event, fed by the runs registry, throttled to 1/s), and `templates.save`, which takes the password step-up and runs a new Pi configuration helper op `templates.write` (`O_NOFOLLOW`, temporary file, `link` or `rename`, 0600).
- **`@pap/ui` stays ignorant of contracts, terminals and RPC.** `Markdown` gains optional tool props (`pathLinks`, `shellHandOff`) that pass through to the lazy renderer. Paths are linked in text nodes and inline code by a component the renderer wraps around them. Shell fences render through `ShellBlock`, a wrapper around the frozen `CodeBlock`.
- **The web wires the tools through seams in `stores/`:**
  - `reply-ports.ts`: per session, the path scope, `openFile` and `toTerminal`. Session tabs register it from the surface bar or switch; agent tabs register it from the agent screen.
  - `files-target.ts`: "open this path at this line" for a Files pane.
  - `terminal-typists.ts`: a terminal pane that can type.
  - `composer-insert.ts`: text for the composer's caret.
- **Pure, tested modules decide everything risky:**
  - `path-links.ts`: what is a path, and where it leads.
  - `shell-text.ts`: what may be typed.
  - `usage.vm.ts`: the meter, hidden rather than guessed.
  - `quote.vm.ts`: the quote text.

**Tech Stack:** TypeScript (erasable), Node 24, zod 4 contracts, React 19, Tailwind 4 tokens, react-markdown 10 + remark-gfm, xterm 6, CodeMirror 6, vitest + happy-dom, Playwright (e2e only).

## Review Focus

1. **A shell block never runs by itself.**
   - Inputs: a trailing new line or blank lines, CRLF, an embedded `ESC[201~` (which ends a bracketed paste early) followed by a line, a C1 CSI (U+009B), a `console` block with output lines, a shell with bracketed paste off.
   - Expected: no byte that executes reaches the shell before the owner's Enter.
   - Tests:
     - T5 `shellText removes ESC, CR, C1 and DEL, so "[201~" in a block cannot end the paste`;
     - T5 `two lines with bracketed paste off type nothing and answer multiline`;
     - T5 journey J17.
2. **A link never leads where Files could not open it.**
   - Inputs: `..`, `~/x`, `//x`, `/etc/passwd`, `/agent/.pi/agent/auth.json`, `/agents/<other id>/home/x` typed in an agent's reply, `example.com/a/b`, `https://…`, a path under the cwd but outside the Files root.
   - Test: T4 `findPaths refuses every escape and maps only /agent/{home,inbox,knowledge}`.
3. **Text that changes under the linker while a reply streams.**
   - Inputs: every prefix of a reply; a path completed character by character; a URL in progress; a growing `:line`.
   - Expected: never a request, never a throw, spans always inside the text, the final spans exact.
   - Tests:
     - T4 `every prefix yields spans inside the prefix, and the whole text exactly these spans`;
     - T4 `no RPC is sent while a reply with paths streams`.
4. **The meter never guesses.**
   - Inputs: a cold session (no loadout), a model without `contextWindow`, a newest reply that was aborted or failed, a compaction or branch summary newer than the last usage, exactly 80 %, usage over the window.
   - Test: T2 `usage.vm.test.ts` (each case named below).
5. **The template write never writes through a link and never replaces a file silently.**
   - Inputs: `prompts/` as a symlink, the target as a symlink to `settings.json`, a hard-linked target, a name created between the check and the write, a reserved name, a description that tries to add YAML keys.
   - Tests: T1 hostile tests (each named below).

**Rulings:**
- **UX1-R1. Method name and home.**
  - The decision: the method is `templates.save` in the skills module (`skills.md` covers Pi's own resources). It runs on the shared Pi write queue (`deps.writes`). The helper op is `templates.write`.
  - Why: the spec leaves the name to the builder, and the skills module already has the helper pool, step-up and queue.
  - Cost if wrong: a rename.
- **UX1-R2. Names.**
  - The decision: the spec's schema, plus a refusal of Pi's built-in command names.
  - Why: Pi 1.1.0's `docs/slash-commands.md` lists them, and a template under one would collide with the built-in. This is the spec's "narrow to Pi's rules".
  - Cost if wrong: an owner who wants `/review` hits nothing; one who wants `/compact` is refused.
- **UX1-R3. The file always has frontmatter.**
  - The decision: `description:` is written JSON-quoted (a JSON string is a valid YAML double-quoted scalar). It defaults to the first non-empty body line, else the name. The body follows exactly as typed.
  - Why: a body that itself starts with `---` must stay body. Checked against Pi's `DefaultResourceLoader` in a scratch run: description, colon, `#`, `---` and backslash round-trip, and the body's own `---` block stays in `content`.
  - Cost if wrong: the `/` menu shows the wrong description.
- **UX1-R4. Audit.**
  - The decision: one row, `kind: "auth"` (the kind of Pi configuration writes, as `models_config_saved`), `reason: "prompt_template_saved"`, `detail: { name }`. The row is written only after a successful write.
  - Cost if wrong: the audit filter differs.
- **UX1-R5. `sensitiveParams: ["name", "replace"]`.**
  - The decision: the body and description are the owner's prompt text, kept out of receipts and logs like a trigger's input (MC30).
  - Cost if wrong: prompt text in a receipt row.
- **UX1-R6. No replace through anything but a regular file.**
  - The decision:
    - Without `replace`, any existing name answers `conflict`, a link included. The final step is `link(temp, target)`, which is atomic: a name created since the check is still `conflict`.
    - With `replace`, a non-regular target answers `config_path_refused` and a hard-linked one `config_hard_link`. The final step is `rename`, which replaces the name, never what a link points at.
  - This refines the spec's "a temporary file then a rename": for a new name, `rename` would silently replace a file created after the check, and `link` cannot.
  - Cost if wrong: a write through a planted link into `auth.json`.

- [ ] **Step 1: Contracts, in full (trust boundary).** `packages/contracts/src/prompt-templates.ts`:
```ts
import { z } from "zod";

/** UX-1 prompt templates: `<Pi agent dir>/prompts/<name>.md`, written by the Pi configuration helper (ADR 0023). */
export const TEMPLATE_LIMITS = { name: 64, description: 200, bodyBytes: 32 * 1024 } as const;

/** Pi's built-in commands (Pi 1.1.0 docs/slash-commands.md): a template under one of these names would collide. */
export const RESERVED_TEMPLATE_NAMES = [
  "settings", "model", "thinking", "scoped-models", "login", "logout", "llama",
  "new", "resume", "name", "session", "tree", "fork", "clone", "compact", "import",
  "copy", "export", "share", "bug", "trust", "reload", "hotkeys", "changelog", "quit",
] as const;
const RESERVED: ReadonlySet<string> = new Set(RESERVED_TEMPLATE_NAMES);

export const PromptTemplateName = z
  .string()
  .min(1)
  .max(TEMPLATE_LIMITS.name)
  .regex(/^[a-z0-9][a-z0-9-]*$/, "lower-case letters, digits and -, starting with a letter or a digit")
  .refine((name) => !RESERVED.has(name), "a Pi command has this name");
export type PromptTemplateName = z.infer<typeof PromptTemplateName>;

// Controls (but tab, LF, CR in a body), line/paragraph separators, lone surrogates and bidi controls: refused, never stripped.
const UNSAFE_BODY = /(?![\t\n\r])\p{Cc}|[\p{Zl}\p{Zp}\p{Cs}]|\p{Bidi_Control}/u;
const UNSAFE_LINE = /[\p{Cc}\p{Zl}\p{Zp}\p{Cs}]|\p{Bidi_Control}/u;
const utf8Bytes = (text: string): number => new TextEncoder().encode(text).length;

export const TemplateDescription = z
  .string()
  .refine((text) => Array.from(text).length <= TEMPLATE_LIMITS.description, "at most 200 characters")
  .refine((text) => !UNSAFE_LINE.test(text), "one plain line");
export const TemplateBody = z
  .string()
  .refine((text) => text.trim() !== "", "a prompt")
  .refine((text) => !UNSAFE_BODY.test(text), "no hidden characters")
  .refine((text) => utf8Bytes(text) <= TEMPLATE_LIMITS.bodyBytes, "at most 32 KiB");

export const TemplatesSaveParams = z
  .object({
    name: PromptTemplateName,
```

```ts
import { randomBytes } from "node:crypto";
import { constants, promises as fs, type Stats } from "node:fs";
import { join } from "node:path";
import { HELPER_OPS, TEMPLATE_LIMITS, type TemplatesSaveParams, type TemplateWriteResult } from "@pap/contracts/pi-host";
import { defineOp, HelperOpError, type HelperContext } from "../ops.ts";

const FOLDER = "prompts";
const UNSAFE_LINE = /[\p{Cc}\p{Zl}\p{Zp}\p{Cs}]|\p{Bidi_Control}/gu;
const errno = (error: unknown): string | undefined => (error as NodeJS.ErrnoException | null)?.code;

/** What Pi reads: one `description` line, JSON-quoted (a YAML double-quoted scalar), then the body exactly as typed (UX1-R3). */
export function templateText(name: string, body: string, description: string | undefined): string {
  const clean = (text: string): string =>
    Array.from(text.replace(UNSAFE_LINE, " ").trim()).slice(0, TEMPLATE_LIMITS.description).join("");
  const first = body.split("\n").map(clean).find((line) => line !== "");
  const line = clean(description ?? "") || first || name;
  return `---\ndescription: ${JSON.stringify(line)}\n---\n${body}`;
}

/**
 * Writes `<agent dir>/prompts/<name>.md` (UX1-R6). The folder is opened without following a link and must be this user's
 * directory; on Linux its descriptor must still name it. The text goes to an exclusive 0600 temporary file beside it, then
 * `link` (no replace: atomic, a name that appeared since the check is `conflict`) or `rename` (replace: the name itself
 * is replaced, never what a link points at). A non-regular or hard-linked target is refused. Residual, as in
 * `pi-file.ts`: another process of the same user can swap a parent folder between the descriptor check and the final step.
 */
export async function writeTemplate(
  ctx: Pick<HelperContext, "agentDir">,
  params: TemplatesSaveParams,
  hooks: { readonly lstat?: (path: string) => Promise<Stats> } = {},
): Promise<TemplateWriteResult> {
  const agentDir = await fs.realpath(ctx.agentDir);
  const folder = join(agentDir, FOLDER);
  try {
    await fs.mkdir(folder, { mode: 0o700 });
  } catch (error) {
    if (errno(error) !== "EEXIST") throw error;
  }
  const dir = await fs
    .open(folder, constants.O_RDONLY | constants.O_DIRECTORY | constants.O_NOFOLLOW)
    .catch((error: unknown) => {
      if (errno(error) === "ELOOP" || errno(error) === "ENOTDIR")
        throw new HelperOpError("config_path_refused", "prompts is not a folder");
      throw error;
    });
  try {
    const info = await dir.stat();
    if (!info.isDirectory() || info.uid !== process.getuid?.())
      throw new HelperOpError("config_path_refused", "prompts folder");
    if (process.platform === "linux" && (await fs.readlink(`/proc/self/fd/${dir.fd}`).catch(() => null)) !== folder)
      throw new HelperOpError("config_path_refused", "prompts folder moved");
    const target = join(folder, `${params.name}.md`);
    const existing = await (hooks.lstat ?? fs.lstat)(target).catch((error: unknown) => {
      if (errno(error) === "ENOENT") return null;
      throw error;
    });
    if (existing !== null && params.replace !== true) throw new HelperOpError("conflict");
    if (existing !== null && !existing.isFile()) throw new HelperOpError("config_path_refused", "not a regular file");
    if (existing !== null && existing.nlink > 1) throw new HelperOpError("config_hard_link");
    const temp = join(folder, `.${params.name}.${randomBytes(6).toString("hex")}.tmp`);
    const handle = await fs.open(
      temp,
      constants.O_WRONLY | constants.O_CREAT | constants.O_EXCL | constants.O_NOFOLLOW | constants.O_NOCTTY,
      0o600,
    );
    try {
      try {
        await handle.writeFile(templateText(params.name, params.body, params.description), "utf8");
        await handle.chmod(0o600);
        await handle.sync();
      } finally {
        await handle.close();
      }
      if (existing !== null) await fs.rename(temp, target);
      else {
        try {
          await fs.link(temp, target);
        } catch (error) {
          if (errno(error) === "EEXIST") throw new HelperOpError("conflict");
          throw error;
        }
        await fs.rm(temp, { force: true });
      }
    } catch (error) {
      await fs.rm(temp, { force: true }).catch(() => undefined); // the first error is the one the daemon needs
      throw error;
    }
    await dir.sync().catch(() => undefined); // the file is in place; a folder sync only guards a power cut
    return { replaced: existing !== null };
  } finally {
    await dir.close().catch(() => undefined);
  }
}

export const templateWriteOp = defineOp({
  params: HELPER_OPS["templates.write"].params,
  run: (params, ctx) => writeTemplate(ctx, params),
});
```

**Rulings:**
- **UX1-R14. The recogniser** (the builder may tighten it, never widen it past the anti-goals).
  - **Tokens:**
    - A token is a maximal run between whitespace and ``()[]{}<>"'`,;|``.
    - Trailing `.,;:!?)]` are stripped, at most 4 characters.
    - The token must then match `^([\p{L}\p{N}._@+\/-]+)(?::([1-9]\d{0,6})(?::[1-9]\d{0,4})?)?$` (`u` flag; greedy and linear: `:` is outside the path class, so the optional `:line` cannot overlap it).
  - **Refused:**
    - `//`, a `.` or `..` segment, a leading `~`, a trailing `/` (folders stay text), and more than 512 characters.
    - A relative token without a `/` and without a known extension. `KNOWN_EXTENSIONS` is a constant of about 60 source, config, document and image extensions, and the stem must be non-empty.
    - A relative token whose first segment holds a `.` without starting with one (`example.com/a`).
    - A bare `Xxx.js` with an upper-case first letter (`Node.js`, `Next.js`).
  - **Resolution:**
    - A relative token resolves against `scope.base`.
    - In an agent scope, the path must be at or under one of `scope.roots`. `/agent/` then maps to `/agents/<agentId>/`.
    - In a plain scope, it must be at or under one of `scope.roots`.
    - Then it must be at or under `scope.filesRoot`.
  - **Bounds:** at most the first 20 000 units of a text and 64 spans.
  - **No request of any kind** (spec: no existence probe).
- **UX1-R15. Where linking happens.**
  - The decision:
    - In `render.tsx`, `p`, `li`, `td`, `th`, `h1` to `h6` and new `strong`, `em` and `del` entries wrap their children in `<PathText>`, which maps string children only.
    - Inline `code` links only with `whole: true`.
    - `a` (links, GFM autolinks included) and `pre` (fences) never link.
    - Your own messages render no `Markdown`, so they never link.
    - Without `pathLinks`, `PathText` returns its children unchanged.
  - Why: UX-2 owns the plugin lists. Components keep UX-1 off that line.
  - Cost if wrong: a path split by emphasis stays text.
- **UX1-R16. Look.**
