**Goal:** pap gets members. The owner invites trusted people. Each member has their own box projects, sessions, agents, triggers, budget, Claude token and GitHub account. The owner keeps the installation, sees members' usage but never their content.

**Roles:**
- `users.role` is `owner` or `member`, and there is exactly one owner (a partial unique index).
- The migration makes the oldest user (`ORDER BY created_at, id LIMIT 1`) the owner.
- The owner holds every permission.
- A member holds every permission except `system:admin`, `pi:*` and `users:*`.
- Cookie sessions get `permissionsOf(role)`. Tokens get the intersection of the token row's permissions, `TOKEN_PERMISSIONS` and `permissionsOf(role)`.
- A token is created with at most its creator's permissions.
- `system:admin` and `users:*` are never-for-tokens.

**Permission moves (S1):**
- `github.startCreate` and `github.forget` become `system:admin`.
- `github.authorizeUrl` and `github.disconnect` become `settings:operate`. They stay in `GITHUB_BROWSER_ONLY`.
- `agents.vm.setClaudeToken` and `agents.vm.clearClaudeToken` become `settings:operate`. They stay browser-only, with their step-up.
- `ops.events.list` and `subscribe.ops` become `system:admin`.

**Invitations:**
- An invitation is a token of 32 random bytes, base64url.
- Only `sha256Hex(token)` is stored.
- It is valid 24 hours and used once.
- The link is `<origin>/invite#token=<token>`, where `<origin>` is the caller's origin checked against `allowedOrigins`.
- Accepting it uses the setup rules: username `^[A-Za-z0-9_.-]{1,64}$`, password 12 to 1024 characters. It creates a member and starts a session with method `password`.
- Failures are counted on `ipKey(ip)` with the setup throttle.

**Budgets:**
- A member's cap is `users.budget_usd` (REAL, USD per day, 0 to 1000). The default for a new member is `5`, the install default.
- `SettingsService.automation(ownerId).dailyBudgetUsd` returns `min(stored, cap)` for a member.
- `settings.set` refuses an `automation.dailyBudgetUsd` above the cap with `budget_cap`.
- The owner has no cap.

**Shared providers:**
- The table is `provider_sharing(provider TEXT PRIMARY KEY, shared INTEGER NOT NULL)`.
- With no row, a provider whose stored auth is `api_key` is shared and any other provider is not.
- A member's box policy models, `sessions.models` and `sessions.availableModels` drop unshared providers.
- OAuth (subscription) providers are never served to boxes: the relay already refuses them (`R/credentials.ts:122`). Their sharing switch is shown disabled with the subscription copy. Subscription use goes through each user's own Claude token.

**Claude token:**
- Each user's token is in the vault's user scope under the name `CLAUDE_TOKEN`.
- At the first start, the legacy file `$PAP_HOME/secrets/claude-token` moves to the owner's vault and the file is removed.
- The relay gets one token per box, which is its owner's.
- A box whose owner has no token gets `claude: false` and the relay's existing `no_claude_token` refusal. Another user's token is never used.

**Host gate:**
- For a member, any path or cwd that is not at or under one of their box project roots (`boxOfPath(source, ownerId, path) !== null`) is refused with `forbidden` before any host file-system call.
- Members never get a host project row, a host worker, a host terminal, a host lane or a lane script.
- Background code checks `auth.isMember(ownerId)` because it has no `Caller`.

**Disable and delete:**
- **Disable** sets `users.disabled_at`. Both `authenticate` paths then refuse, so the next WebSocket frame fails and tokens answer 401. Their boxes and agent VMs stop, and triggers refuse with `paused`. Data stays.
- **Enable** clears `users.disabled_at`.
- **Delete** asks the step-up, then:
  - stops everything;
  - box projects go to the trash as a project delete does;
  - agents go to the agent trash;
  - triggers, sessions, the vault (every scope of the owner), push subscriptions and every `owner_id` row are deleted;
  - finally the `users` row is deleted, which cascades to sessions, passkeys and tokens.
- The owner can be neither disabled nor deleted: `forbidden`.

**CLI:**
- `pap user add <username> [--password-stdin] [--role owner|member]`:
  - with no user, it creates the owner;
  - once an owner exists, it creates a member;
  - `--role owner` is refused when an owner exists (exit 1, "an owner already exists").
- `pap passkey reset [<username>] [--revoke-tokens] [--keep-password] [--password-stdin]`:
  - the default user is the owner;
  - every delete is scoped to that user;
  - `secrets/device.key` is removed only for the owner.

**Errors (new codes):**
- `budget_cap` (`settings.set` above the cap).
- `account_disabled` (a correct sign-in to a disabled account).
- `invite_invalid` (HTTP only: an unknown, used or expired invitation).
