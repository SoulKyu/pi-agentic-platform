**Goal:** a stranger installs pap with one command on a Linux host and gets a working, secure instance: a systemd **user** service bound to localhost, the one-time setup URL printed, then the owner's passkey (spec A success criterion 3). Exactly **two install methods** (decision 87).

**The two methods (recommended; owner question Q1):**

| | Method 1: git checkout | Method 2: offline archive |
|---|---|---|
| Command | `scripts/install.sh` in a clone | `./pap-install-<id>.sh` next to `pap-<id>-linux-x64.tar.gz` |
| Built by | the target host (`pnpm install --frozen-lockfile`, `pnpm build`; node-pty compiles: gcc, g++, make, python3) | `pnpm build:archive` on a build host, copied (scp, USB) |
| Network on the target | yes, once (registry, corepack) | none |
| Toolchain on the target | Node 24.14+, build toolchain | none (the archive carries its Node runtime and a compiled node-pty); glibc at least the build host's |
| Integrity | the lockfile (`--frozen-lockfile`) and git | SHA-256 of the archive **pinned inside the installer script** at build time |
| Hosting | none | none (no public host needed; the GitHub mirror is private) |
| Cost to this repo | one script | one builder, one installer template |

**Private repository now, public at v1 (owner input, 2026-10-15).** The GitHub repository stays private until v1 and becomes public at v1.
- **Works now on the private repo:** both recommended methods. Method 1 needs a clone, which the owner makes with his own credentials (a stranger cannot clone yet, which is fine before v1). Method 2 downloads nothing: the three files are copied by hand.
- **Only at v1:** a hosted download. Attaching `pap-<id>-linux-x64.tar.gz`, its `.sha256` and `pap-install-<id>.sh` to a **GitHub Release** makes `curl -fLO <release asset>` possible for a stranger, and a plain `git clone` of the public repo makes method 1 stranger-friendly. No change to the scripts is needed for either: the installer already reads the archive next to itself.
- **Must wait for M6b / v1:** publishing releases (a release workflow, release-please, the upload step) and any `curl | sh` one-liner. Caution recorded for M6b: a pinned hash published on the same host as the archive protects against corruption and a swapped asset only if the installer script is obtained over a separate trusted channel (the public repository at a tagged commit, or a signature); a one-liner that fetches script and archive from the same release proves nothing against a compromised account. Signing (cosign) stays after v1 (decision 75).
- **Nothing in M6 is blocked by this.** M6 adds no workflow that publishes, and no URL is hard-coded anywhere.

**Architecture:**
- Both scripts are thin: they check prerequisites, put the files in place and call `pap service install --node <abs> --main <abs>`. All unit rendering, linger handling, restart, readiness, the setup-URL reading and the `pap` launcher live in TypeScript (`apps/daemon/src/cli/service/`), where it is unit-testable and one code path serves both methods.
- `pap service install | uninstall | url` do not open `$PAP_HOME` and take no instance lock: they only write `~/.config/systemd/user/pap.service` and the launcher `~/.local/bin/pap`, and talk to `systemctl --user`, `loginctl`, `journalctl --user` through argument lists (no shell).
- Archive layout on the target: `~/.local/share/pap/releases/<id>/` (0700), `current -> releases/<id>` (relative symlink, switched with `mv -T` only once the archive is verified and complete, and put back if `service install` then fails), the previous release kept (M6b's rollback), older ones pruned last, after the service is up. The unit points at `current/...`, so a later update never rewrites it. Method 1 points the unit at the checkout's `apps/daemon/dist/main.js` (a later `git pull`, rebuild or delete changes or breaks the running code with no integrity check: install.md says so).
- `~/.local/bin/pap` (owner i6, M6R37) is a 0755 launcher written by `pap service install` for both methods, so the recovery commands (`pap passkey reset`, `pap user add`, `pap audit prune`, `pap service uninstall`) exist after an install. No `PATH` edit, ever.
- The setup URL is read from the user journal (owner i5): the daemon already logs it as the info line `setup_url` (`main.ts`), and the unit's invocation id selects exactly this start's lines (the token lives in memory and changes at each start). **Readiness is the daemon's own `listening` line** (`daemon.ts`, logged after the server is bound), never `is-active`: the unit is `Type=simple`, which is "active" right after the fork (M6R7).

## Global Constraints

Binding ones from M9 and M10, restated for this milestone:
- 400 lines per file at most, test files included, no baseline. Daemon modules import only `@pap/contracts`, `kernel/` and other modules' `index.ts`; the new code is CLI code under `apps/daemon/src/cli/` and may import `kernel/` and `../shutdown.ts`.
- TypeScript: erasable syntax only (no enum, namespace, parameter properties); relative imports keep their `.ts` extension. The only ESLint directive is `eslint-disable-next-line <rule> -- <reason>`.
- Tests never touch `~/.pi/agent`, `~/.pap`, the real user manager or the network: every test runs in a temporary `HOME` with fake `systemctl`, `loginctl`, `journalctl` (and `pnpm`, `node` for the shell scripts) first on `PATH`. No sleeps: the setup-URL wait goes through the CLI `Clock` (`io.clock.sleep`).
- Every child process is started with an argument list (`execFile`), never a shell, with a fixed binary name, a timeout and an output cap. No secret on any command line; this milestone handles none (the setup URL is printed, never passed as an argument).
- Logs and CLI messages never carry raw child stderr (MC57): a failed `systemctl` call is reported as a fixed sentence plus the exit code, and the hint `journalctl --user -u pap -n 30`.
- A message never overstates safety: the integrity sentence says "the archive matches the checksum pinned in this script", not "the archive is safe".
- Literal characters: no literal bidi, zero-width or line-separator characters in source, scripts or this plan (checked with the Cf / Zl / Zp scan in T7).
- Conventional Commits, rebase on `main` before the PR, no AI attribution trailer, no `Co-Authored-By`.

M6 additions:
- **Linux and systemd only.** Method 1 runs on any architecture with Node 24 and the build tools; the archive (method 2) is linux-x64 and glibc only and its installer refuses other platforms with one sentence.
- **No sudo anywhere.** Both installers refuse to run as root. Nothing is piped from the network into a shell. Nothing is written outside `$HOME`.
- **Localhost by default.** The unit never contains `--host`, `--insecure-http`, `--tls-*`. (Loopback plain HTTP is the daemon's default and is covered by ADR 0004.)
- **`~/.pap` is never touched by install or uninstall.** The unit sets `UMask=0077`; the daemon creates and tightens `$PAP_HOME` itself (`prepareHome`, 0700). Uninstall removes only the unit.
- **File modes:** unit 0644 (no secret in it), launcher `~/.local/bin/pap` 0755 (fixed text, no secret), `~/.local/share/pap` and `releases/` 0700, installer scripts 0755, the archive built with `--owner=0 --group=0`, extracted with `--no-same-owner --no-same-permissions` under `umask 077`.
- **bubblewrap is a prerequisite that is warned about, never installed** (C5): both installers print `bubblewrap not found: agents that require the sandbox will not start (sudo apt install bubblewrap)` when `${PAP_BWRAP:-/usr/bin/bwrap}` is missing or not root-owned, and continue. The sentence is a hint for the owner to run, not a command the script runs.

## Review Focus

The spec says "a stranger installs it in one step". These are the inputs most likely to bite that person and that no happy-path test shows; each has a test in the named task.
1. A `HOME` or checkout path with a space, `%`, a quote, a trailing slash or a newline: the unit must never be written with it (systemd would split or expand it). Expected: one-sentence refusal naming the flag (or, in the archive installer, `HOME`, **before the checksum, the copy and any extraction**), nothing written. (T1, T2, T5)
2. Reinstalling over a running install: `~/.pap` and its database stay byte-identical; the running service is restarted with the new code; a failed second install (checksum, or `service install` itself failing) leaves the first one in `current` and restarts it. (T2, T5)
3. A truncated, edited or re-packed archive (wrong checksum; right checksum but a member outside `pap-<id>/`; the file swapped after the hash): nothing is extracted into place and `current` is untouched; every step after the private copy reads the copy only. (T5)
4. No systemd user manager (an ssh session without `XDG_RUNTIME_DIR`), or linger off: a clear sentence with the exact fix before anything is built or extracted; with linger off the installer enables it itself (no sudo; 15 s cap if polkit prompts on a non-tty) or prints the one command. (T2, T3, T5)
5. The port is taken (the owner's `pap-preview` on 7777) or another pap holds `$PAP_HOME`: `systemctl is-active` still says active for the first moments, so the command waits for the daemon's own `listening` line; without it the command exits 1 with the journal hint, never printing a setup URL that nobody serves and never claiming an owner exists. Only "listening and no setup URL" means an owner already exists. The unit gives up after 5 starts in 120 s instead of looping forever. (T1, T2)
6. After the install the recovery commands work: `~/.local/bin/pap` exists, is ours, and says so when `~/.local/bin` is not on `PATH`; an existing foreign file there is never overwritten. (T1, T2)

## Plan conventions (decided by this plan)

- **M6R1** `pap service` commands take no instance lock and never open `$PAP_HOME`. Why: they must work while the daemon runs (reinstall) and must not create a home as a side effect. Cost if wrong: an install on a host whose home is corrupt succeeds and the daemon then refuses to boot, visible in the journal hint.
- **M6R2** The unit is a fixed template in code with three allowlisted inputs (`--node`, `--main`, `--home`) and one number (`--port`). Why: the whole injection surface is `SAFE_PATH`. Cost if wrong: a path with `%h` or a space reaches systemd.
- **M6R3** (corrected by M6-RT-07, C4, cross-plan agreements 4 and M6-RT section 3) The unit environment is `PATH=<node dir>:/usr/local/bin:/usr/bin:/bin` (absolute entries only, the shape `unattendedEnv` keeps) and `PAP_HOME` only when given. **Hardening: `NoNewPrivileges=yes`, `RestrictSUIDSGID=yes`, `LockPersonality=yes`.** Measured here (C4): `setpriv --no-new-privs bwrap --ro-bind / / --unshare-user --unshare-pid --dev /dev --proc /proc true` exits 0 on this Ubuntu host (AppArmor userns profile), and `systemd-analyze verify --user` accepts the unit; `systemd-run --user --scope` from inside a service with these directives is not testable without the real manager, so T2 step 5 checks it by hand and, if a worker scope fails, drops `NoNewPrivileges` only and records why in ADR 0056. **Never add** `ProtectHome`, `PrivateTmp`, `RestrictNamespaces`, `PrivateUsers` or a `SystemCallFilter` without `@mount` and `unshare` (M11's bwrap sandbox needs user namespaces and `PAP_BWRAP` is not set by the unit). **No secret, provider key or M11 env in the unit**: secrets stay in `$PAP_HOME`. `[Unit]` carries `StartLimitIntervalSec=120` and `StartLimitBurst=5` (with `RestartSec=5` a port that is taken fails after 5 starts, not forever). Cost if wrong: a stricter unit is a one-line follow-up in M6b.
- **M6R4** `TimeoutStopSec` is `ceil(STOP_DEADLINE_MS / 1000) + 10` from `apps/daemon/src/shutdown.ts`, so systemd never SIGKILLs a daemon that is still shutting down gracefully. Cost if wrong: killed workers, a stale lock (the boot sweep recovers).
- **M6R5** Linger (owner i2): the installer checks `loginctl show-user <uid> --property=Linger --value`; when `no` it runs `loginctl enable-linger` (allowed for the caller by the default polkit policy, no sudo; capped at 15 s because polkit may prompt on a non-tty ssh, and a timeout counts as a refusal) and re-checks; if still `no` it prints `loginctl enable-linger <user>` as a warning and continues (the service works while a session exists; worker scopes need linger and the daemon already warns at boot). Cost if wrong: a service that stops at logout on a VPS.
- **M6R6** Reinstall restarts the running service (`systemctl --user restart pap.service`): running turns are interrupted, sessions and `$PAP_HOME` survive (the daemon shuts down gracefully, M2). The command says so in one line. Q3.
- **M6R7** (corrected by M6-RT-01, M6-RT-06) Readiness and the setup URL come from the user journal, selected by `InvocationID` (32 hex characters, validated), read by `readJournal` (one pass: did the daemon log `listening`, and the last loopback `http:` `setup_url`). **`is-active` is not readiness** (`Type=simple`). Outcomes, in this order: `listening` seen with a URL: print it; `listening` seen without a URL: "an owner already exists" (the only case where that sentence is true); no `listening` line after 40 reads (`io.clock.sleep(500)`, about 20 s): exit 1 with the journal hint and no URL, because the daemon never bound (port taken, home locked, crash loop). If the match on the invocation id returns nothing, `journal()` retries with `--since "<restart time> UTC"` (the format is validated) instead of failing: whether a user unit's lines carry `_SYSTEMD_INVOCATION_ID` or only `USER_INVOCATION_ID` is unverified on this host, so T2 step 5 records which one matched.
- **M6R8** Release id = `<package version>-<git sha7>[-dirty]-<UTC yyyymmddHHMM>`, matched by `/^[A-Za-z0-9._-]{1,64}$/` before it goes into any file name or template. The archive builder refuses a dirty tree without `--allow-dirty`.
- **M6R9** The installer template is filled with four validated values; nothing else is interpolated. The SHA-256 is of the final `.tar.gz`. The installer is the only integrity check and the doc says so: it protects against corruption and tampering in transit **if the script itself came over a trusted channel**; it does not protect against a compromised build host (signing is M6b).
- **M6R10** Both installers forward their remaining arguments (`"$@"`) to `pap service install`, so `--port` and `--home` work from the first command (the owner's by-hand check runs beside the preview on port 7777 this way).
- **M6R11** The archive carries the **builder's own Node binary** (`process.execPath`, must be 24.14 to 24.x) and its license text (`<node prefix>/LICENSE`; the build refuses when it is absent, i.e. a distro Node without it). Why: no download at build time. Cost if wrong: a Node that links system libraries not present on the target (glibc check covers the common case).
- **M6R12** `MIN_GLIBC` in the installer is the build host's `getconf GNU_LIBC_VERSION`; build on the oldest host you target (a podman `ubuntu:22.04` shell works). Q4.

**Red-team and agreement rulings:**
- **M6R37** (M6-RT-03) Launcher: `pap service install` writes `<bin-dir>/pap` (default `$HOME/.local/bin`, flag `--bin-dir <abs>` so a by-hand try never replaces the owner's real launcher) with fixed text: `#!/bin/sh`, a marker comment, `PAP_HOME='<home>'; export PAP_HOME` only when `--home` was given (recovery commands then target the same home as the unit), and `exec '<node>' --disable-warning=ExperimentalWarning '<main>' "$@"`. The three paths went through `safePath`, so a single quote cannot be closed. Written atomically (`wx` temp file, mode 0755, rename). A regular file without the marker, or a symlink, at the target is **foreign**: never replaced, a warning names it. `uninstall` removes it only when it carries the marker. Same code path for both methods; M11 adds no CLI command and inherits it. The launcher sits under the home, so agent sandboxes do not see it (agreement 11).
- **M6R38** (M6-RT-02, RT-05, RT-08, RT-09) Archive installer order: refuse root, platform and a `HOME` that is not safe (`[A-Za-z0-9._+@/-]` only, absolute, no `//`, no `..`, no trailing `/`, at most 900 characters, same rule as `safePath`) **before anything is hashed, copied or written**; prerequisites; remove stale `releases/.stage.*` (one installer at a time is assumed, not enforced); copy the archive once into the 0700 stage folder and hash, list and extract **that copy only**; a half-moved or corrupted `releases/<id>` (no `node/bin/node` or no `main.js`) is replaced; `current` is switched only after verification and **put back (and the service restarted) when `service install` fails**; releases other than the new and the previous are pruned last, after `service install` succeeded. Cost: the archive is copied once (disk for one extra archive during the install).
- **M6R39** (M6-RT-04) The archive stage carries an allowlisted `.npmrc` (only `engine-strict`) or none, never the builder's file; the builder scans the staged `.npmrc`, `package.json` files and `pnpm-workspace.yaml` for `_authToken`, `_password`, `//registry` credentials and `npm_` tokens and refuses; it deletes `node_modules/.modules.yaml` (builder store path) before tarring.
- **M6R40** (M6-RT-10) Method 1 resolves the Node binary with `node -p process.execPath` (a volta / asdf shim is not a binary: its directory would be the shim directory on the unit's `PATH`) and passes that to `--node`.
- **M6R41** (M6-RT-12) The determinism claim is "byte-identical given the same staged tree"; real pnpm output (hardlinks, mtimes) is covered by `--sort=name --mtime`, verified here across two runs two seconds apart, not by the fake-runner test.
- **M6R42** (C5, agreement 6) Both installers warn, never install, when bubblewrap is missing or not root-owned (Global Constraints). install.md names Ubuntu's AppArmor userns profile (`apparmor_restrict_unprivileged_userns`) and the `systemctl --user edit pap` drop-in with `Environment=PAP_BWRAP=/path/to/bwrap` for a non-standard location (agreement 8; the unit never sets it). M11 Settings > Agents remains the probe.
- **M6R43** (agreement 7) install.md says the unit's `<node dir>` under the home is hidden inside M11 sandboxes, so agent shells have no `node` unless it is installed system-wide.
- **M6R44** (C1, agreements 1 to 3, 5, 12, 13) Merge order and shared files are in "Merge order and conflict notes". Backups (M6b) treat `secrets/vault/key` separately and promise nothing about M11's copy. The heavy gate takes one `flock` shared with M11's lanes.

**Rulings (pre-dispatch):**
- M6R2, M6R3, M6R4 (see conventions).
- M6R13 `SAFE_PATH` allows `[A-Za-z0-9._+@/-]` only, absolute, no `..` segment, no `//`, at most 1024 characters. Why: systemd splits `ExecStart` on whitespace, expands `%` specifiers and `$`, and treats `\` and quotes specially; an allowlist is shorter than a correct quoting layer. Cost if wrong: the install refuses a legitimate unusual path (visible, fixable); a looser rule would write an injectable unit.

```ts
// apps/daemon/src/cli/service/unit.ts
import { dirname } from "node:path";

/** Absolute, no `..` segment, only characters that mean nothing to systemd (no space, quote, `%`, `$`, `\`, `;`). */
const SAFE_PATH = /^\/[A-Za-z0-9._+@/-]{1,1023}$/;

export class UnitInputError extends Error {
  override name = "UnitInputError";
}

export function safePath(label: string, value: string): string {
  if (!SAFE_PATH.test(value) || value.split("/").includes("..") || value.includes("//"))
    throw new UnitInputError(
      `${label} must be an absolute path of letters, digits and . _ + @ / - only (got ${JSON.stringify(value.slice(0, 80))})`,
    );
  return value;
}

export interface UnitInput {
  readonly node: string;
  readonly main: string;
  readonly port?: number;
  readonly home?: string;
  readonly stopTimeoutSec: number;
}

export function renderUnit(input: UnitInput): string {
  const node = safePath("--node", input.node);
  const main = safePath("--main", input.main);
  if (input.port !== undefined && !(Number.isInteger(input.port) && input.port >= 1 && input.port <= 65_535))
    throw new UnitInputError("--port must be an integer from 1 to 65535");
  const path = [...new Set([dirname(node), "/usr/local/bin", "/usr/bin", "/bin"])].join(":");
  const exec = [node, "--disable-warning=ExperimentalWarning", main, "serve"];
  if (input.port !== undefined) exec.push("--port", String(input.port));
  return [
    "[Unit]",
    "Description=pap (self-hosted agentic platform)",
    "StartLimitIntervalSec=120",
    "StartLimitBurst=5",
    "",
    "[Service]",
    `ExecStart=${exec.join(" ")}`,
    `Environment=PATH=${path}`,
    ...(input.home === undefined ? [] : [`Environment=PAP_HOME=${safePath("--home", input.home)}`]),
    "UMask=0077",
    "NoNewPrivileges=yes",
    "RestrictSUIDSGID=yes",
    "LockPersonality=yes",
    "Restart=on-failure",
    "RestartSec=5",
    `TimeoutStopSec=${input.stopTimeoutSec}`,
    "",
    "[Install]",
    "WantedBy=default.target",
    "",
  ].join("\n");
}

export interface JournalFacts {
  readonly listening: boolean;
  readonly setupUrl: string | null;
}

const LOOPBACK = new Set(["localhost", "127.0.0.1", "[::1]"]);
/** One pass over the journal text of one start: did the daemon log `listening`, and what is its last loopback setup_url. */
export function readJournal(journal: string): JournalFacts {
  let listening = false;
  let setupUrl: string | null = null;
  for (const line of journal.split("\n")) {
    const wantsListening = line.includes('"listening"');
    if (!wantsListening && !line.includes('"setup_url"')) continue;
    try {
      const entry = JSON.parse(line) as { msg?: unknown; url?: unknown };
      if (entry.msg === "listening") listening = true;
      if (entry.msg !== "setup_url" || typeof entry.url !== "string" || entry.url.length > 2048) continue;
      const url = new URL(entry.url);
      if (url.protocol === "http:" && LOOPBACK.has(url.hostname)) setupUrl = url.href;
    } catch {
      /* a torn or foreign line */
    }
  }
  return { listening, setupUrl };
}
```

The launcher (`apps/daemon/src/cli/service/launcher.ts`, run before written: writes 0755, runs with `$@` and `PAP_HOME`, a foreign file and a foreign symlink are kept, a path with a space or a quote is refused):

```ts
import { chmodSync, lstatSync, mkdirSync, readFileSync, renameSync, rmSync, writeFileSync } from "node:fs";
import { join } from "node:path";
import { safePath } from "./unit.ts";

export const LAUNCHER_MARK = "# pap launcher (written by pap service install)";

/** Fixed text; the three inputs went through `safePath`, so single quotes cannot be closed from inside. */
export function renderLauncher(input: { node: string; main: string; home?: string }): string {
  const node = safePath("--node", input.node);
  const main = safePath("--main", input.main);
  return [
    "#!/bin/sh",
    LAUNCHER_MARK,
    ...(input.home === undefined ? [] : [`PAP_HOME='${safePath("--home", input.home)}'`, "export PAP_HOME"]),
    `exec '${node}' --disable-warning=ExperimentalWarning '${main}' "$@"`,
    "",
  ].join("\n");
}

const ours = (target: string): boolean | null => {
  try {
    const stat = lstatSync(target);
    return stat.isFile() && readFileSync(target, "utf8").includes(LAUNCHER_MARK);
  } catch {
    return null; // absent
  }
};

/** "foreign": a file or link that is not ours sits at the target; it is never replaced. */
export function writeLauncher(binDir: string, content: string): "written" | "foreign" {
  const dir = safePath("--bin-dir", binDir);
  const target = join(dir, "pap");
  if (ours(target) === false) return "foreign";
  mkdirSync(dir, { recursive: true, mode: 0o755 });
  const temp = `${target}.tmp-${process.pid}`;
  writeFileSync(temp, content, { flag: "wx", mode: 0o755 });
  chmodSync(temp, 0o755);
  renameSync(temp, target);
  return "written";
}

export function removeLauncher(binDir: string): void {
  const target = join(safePath("--bin-dir", binDir), "pap");
  if (ours(target) === true) rmSync(target);
}
```

```ts
import { execFile } from "node:child_process";
import { CliError } from "../open-home.ts";

type Bin = "systemctl" | "loginctl" | "journalctl";
const PASS_ENV = ["PATH", "HOME", "XDG_RUNTIME_DIR", "DBUS_SESSION_BUS_ADDRESS", "LANG"] as const;
const INVOCATION_ID = /^[0-9a-f]{32}$/;
const UNIT_NAME = /^[a-z][a-z0-9-]{0,40}\.service$/;

function run(env: NodeJS.ProcessEnv, bin: Bin, args: readonly string[], timeout = 15_000): Promise<{ code: number; stdout: string }> {
  const childEnv: NodeJS.ProcessEnv = {};
  for (const name of PASS_ENV) if (env[name] !== undefined) childEnv[name] = env[name];
  return new Promise((resolve, reject) => {
    execFile(bin, [...args], { env: childEnv, timeout, maxBuffer: 1_048_576, windowsHide: true }, (error, stdout) => {
      if (error === null) return resolve({ code: 0, stdout });
      const code = (error as { code?: unknown }).code;
      if (typeof code === "number") return resolve({ code, stdout });
      reject(new CliError(`${bin} could not be run`, 1)); // ENOENT, timeout, output cap: a fixed sentence
    });
  });
}

const must = async (env: NodeJS.ProcessEnv, bin: Bin, args: readonly string[]): Promise<string> => {
  const { code, stdout } = await run(env, bin, args);
  if (code !== 0) throw new CliError(`${bin} ${args[1] ?? args[0]} failed (exit ${code})`, 1);
  return stdout;
};
```

```bash
#!/usr/bin/env bash
# Method 1: install pap from this git checkout as a systemd user service. Needs the network once (the registry).
set -euo pipefail

die() { printf 'pap-install: %s\n' "$*" >&2; exit 1; }
warn() { printf 'pap-install: warning: %s\n' "$*" >&2; }

[ "$(id -u)" -ne 0 ] || die "do not run as root: pap is a user service"
[ "$(uname -s)" = Linux ] || die "linux only"
repo="$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")/.." && pwd -P)"
[ -f "$repo/pnpm-workspace.yaml" ] && [ -d "$repo/apps/daemon" ] || die "not a pap checkout: $repo"

command -v node >/dev/null 2>&1 || die "node 24.14 or newer 24.x is required (not found)"
node_version="$(node -p 'process.versions.node')"
IFS=. read -r major minor _ <<<"$node_version"
{ [ "$major" = 24 ] && [ "${minor:-0}" -ge 14 ]; } || die "node $node_version found; pap needs >=24.14 <25"
node_bin="$(node -p 'process.execPath')"   # the real binary, not a volta / asdf shim
[ -x "$node_bin" ] || die "cannot resolve the node binary"
for tool in gcc g++ make python3 systemctl; do
  command -v "$tool" >/dev/null 2>&1 || die "missing tool: $tool (node-pty is compiled at install: gcc, g++, make, python3)"
done
systemctl --user show-environment >/dev/null 2>&1 \
  || die "no systemd user manager (log in with a full session, or set XDG_RUNTIME_DIR=/run/user/$(id -u))"
bwrap_path="${PAP_BWRAP:-/usr/bin/bwrap}"
{ [ -x "$bwrap_path" ] && [ "$(stat -c %u -- "$bwrap_path")" = 0 ]; } \
  || warn "bubblewrap not found: agents that require the sandbox will not start (sudo apt install bubblewrap)"

if command -v pnpm >/dev/null 2>&1; then
  pnpm_cmd=(pnpm)
elif command -v corepack >/dev/null 2>&1; then
  pnpm_cmd=(corepack pnpm)
else
  die "pnpm not found; enable it with: corepack enable"
fi

cd -- "$repo"
"${pnpm_cmd[@]}" install --frozen-lockfile
"${pnpm_cmd[@]}" build
main="$repo/apps/daemon/dist/main.js"
[ -f "$main" ] && [ -f "$repo/apps/web/dist/index.html" ] || die "the build left no apps/daemon/dist/main.js or apps/web/dist"

exec "$node_bin" --disable-warning=ExperimentalWarning "$main" service install --node "$node_bin" --main "$main" "$@"
```

```bash
readonly ARCHIVE_NAME="@@ARCHIVE_NAME@@"
readonly MIN_GLIBC="@@MIN_GLIBC@@"

die() { printf 'pap-install: %s\n' "$*" >&2; exit 1; }
warn() { printf 'pap-install: warning: %s\n' "$*" >&2; }

[ "$(id -u)" -ne 0 ] || die "do not run as root: pap is a user service"
[ "$(uname -s)" = Linux ] && [ "$(uname -m)" = x86_64 ] || die "this archive is for linux-x64"
case "${HOME:-}" in /*) ;; *) die "HOME must be an absolute path" ;; esac
case "$HOME" in
  *[!A-Za-z0-9._+@/-]* | *//* | */ | */.. | */../*)
    die "HOME holds a character that is not safe in a systemd unit (only letters, digits and . _ + @ / - are allowed): install from a checkout under a safe path with scripts/install.sh" ;;
esac
[ "${#HOME}" -le 900 ] || die "HOME is too long"
for tool in tar sha256sum awk sort getconf systemctl cp; do
  command -v "$tool" >/dev/null 2>&1 || die "missing tool: $tool"
done
systemctl --user show-environment >/dev/null 2>&1 \
  || die "no systemd user manager (log in with a full session, or set XDG_RUNTIME_DIR=/run/user/$(id -u))"
host_glibc="$(getconf GNU_LIBC_VERSION | cut -d' ' -f2)"
[ "$(printf '%s\n%s\n' "$MIN_GLIBC" "$host_glibc" | sort -V | head -n1)" = "$MIN_GLIBC" ] \
  || die "glibc $host_glibc is older than $MIN_GLIBC, which this archive was built against"
bwrap_path="${PAP_BWRAP:-/usr/bin/bwrap}"
{ [ -x "$bwrap_path" ] && [ "$(stat -c %u -- "$bwrap_path")" = 0 ]; } \
  || warn "bubblewrap not found: agents that require the sandbox will not start (sudo apt install bubblewrap)"

source_archive="$(cd -- "$(dirname -- "$0")" && pwd -P)/$ARCHIVE_NAME"
[ -f "$source_archive" ] && [ ! -L "$source_archive" ] || die "$ARCHIVE_NAME must sit next to this script (and not be a symbolic link)"

app="$HOME/.local/share/pap"
rel="$app/releases/$RELEASE_ID"
mkdir -p -m 700 "$app" "$app/releases"
rm -rf -- "$app"/releases/.stage.*   # leftovers of an installer that was killed; one installer at a time
stage="$(mktemp -d "$app/releases/.stage.XXXXXX")"
switched=0
previous=""
cleanup() {
  status=$?
  rm -rf -- "$stage"
  if [ "$status" -ne 0 ] && [ "$switched" = 1 ]; then
    if [ -n "$previous" ]; then
      ln -sfn -- "releases/$previous" "$app/current.new" && mv -T -- "$app/current.new" "$app/current" || true
      systemctl --user restart pap.service >/dev/null 2>&1 || true
      printf 'pap-install: the previous release (%s) is back in place\n' "$previous" >&2
    else
      rm -f -- "$app/current"
    fi
  fi
}
trap cleanup EXIT

# From here on only the private copy is read: the file next to this script is never named again.
copy="$stage/archive.tar.gz"
cp -- "$source_archive" "$copy"
actual="$(sha256sum -- "$copy" | cut -d' ' -f1)"
[ "$actual" = "$EXPECTED_SHA256" ] || die "checksum mismatch: nothing was installed (expected $EXPECTED_SHA256, got $actual)"

tar -tzf "$copy" | awk -v prefix="pap-$RELEASE_ID/" '
  index($0, prefix) != 1 || $0 ~ /(^|\/)\.\.(\/|$)/ { bad = 1 }
  END { exit bad }' || die "the archive holds a path outside pap-$RELEASE_ID/"

mkdir -m 700 "$stage/x"
tar -xzf "$copy" -C "$stage/x" --no-same-owner --no-same-permissions
complete() { [ -x "$1/node/bin/node" ] && [ -f "$1/app/apps/daemon/dist/main.js" ]; }
complete "$stage/x/pap-$RELEASE_ID" || die "the archive holds no node runtime or no daemon"

if [ -e "$rel" ] && ! complete "$rel"; then rm -rf -- "$rel"; fi   # a half-moved or corrupted earlier folder
if [ ! -e "$rel" ]; then mv -T -- "$stage/x/pap-$RELEASE_ID" "$rel"; fi

if [ -L "$app/current" ]; then previous="$(basename -- "$(readlink -- "$app/current")")"; fi
ln -sfn -- "releases/$RELEASE_ID" "$app/current.new"
mv -T -- "$app/current.new" "$app/current"
switched=1

node="$app/current/node/bin/node"
main="$app/current/app/apps/daemon/dist/main.js"
"$node" --disable-warning=ExperimentalWarning "$main" service install --node "$node" --main "$main" "$@"

for dir in "$app"/releases/*/; do
  name="$(basename -- "$dir")"
  [ "$name" = "$RELEASE_ID" ] || [ "$name" = "$previous" ] || rm -rf -- "$dir"
done
```
