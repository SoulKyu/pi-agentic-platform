De M0 à la v1

16 jalons (M6b et M14 ajoutés le 15, décision 87). M0 + M1 posent les preuves techniques et le squelette ; la v1 = M2 → M13. Chaque jalon reçoit son plan détaillé (tâches, modèles, estimation) avant de démarrer, validé par toi. Depuis M5, deux jalons tournent à la fois, dans l'ordre choisi par la décision 75 : M8 + M7, puis M9 + M10, puis M11 + M6, puis M12, puis M13. État au 2026-10-15 : les vagues 0 à 4 sont terminées (M0 → M5, M7 → M10) ; la prochaine est M11 + M6.

Décisions qui t'attendent

vague 5 · maintenant

Lancer M11 + M6

Toutes leurs dépendances sont mergées (M7, M9, M10 pour M11 ; M5 pour M6). Prochaine étape : brief de planification commun, page de questions, puis les deux plans avec leur tableau de modèles, à valider avant l'exécution.

M6 · page de questions

Les deux méthodes d'installation de M6

M6 reste ultra-simple (décision 87) : deux méthodes seulement, à choisir sur la page de questions de M11 + M6. Le reste (image OCI, npm, mise à jour avec rollback, canaux, backup / restore, release) passe en M6b, toujours dans la v1. R52b (podman rootless, systempaths=unconfined) suit l'image OCI : M6b, ou M6 si tu choisis une méthode OCI.

M14 · après M11

Intégration GitHub

Clone et fork d'un dépôt distant, plus d'aide GitHub, un token GitHub par utilisateur à la place du login gh. Proposé, pas planifié : il faut un ADR (stockage chiffré par utilisateur sur les secrets de M11, scopes, jamais dans les scripts ni l'agent, révocation, GitHub App ou tokens).
