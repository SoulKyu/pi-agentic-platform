# Boxes lot B1 (projects and their sessions in a box) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a project created from a name lives in its own microVM box. Its sessions, children and trigger tasks run there, and Files, Changes and knowledge go through the guest. The host never reads or runs anything of it.

**Architecture:**
- **S1, shared:** on the join branch, S1 writes the shared contracts and the daemon port types (`BoxRef`, guest op schemas, `BoxOps`, `BoxControl`, `ProjectBoxSource`), plus their fakes.
- **Lane A, the VM stack (A1 to A7):** box identity through pap-vmd and the daemon, project box launches, the `project` policy profile, guest operations, images and box control, network requests.
- **Lane B, product and UI (B1 to B7):** projects as boxes, session and task resolution, the Files, Changes and knowledge backends, search over mirrors, prechecks removed, the web.
- **Join (J1 to J3):** merge, compose, int journeys, docs, one Opus final review, the root window.

**Tech Stack:** TypeScript (erasable syntax), Node 24, zod, vitest, SQLite migrations, React, the agent microVM stack (pap-vmd, the gateway, the guest, the process backend).

**Spec:** `docs/specs/2026-10-23-boxes-b1-design.md`. Programme: `docs/specs/2026-10-23-boxes-design.md`. Recon maps (exact paths and line numbers; copy them into the SDD workspace at setup): `b1-recon-vm.md`, `b1-recon-product.md` (scratchpad of the planning session). The SDD workspace keeps them as `.superpowers/sdd/boxes-b1/recon-{vm,product}.md`.

## Review Focus

1. A path under a box project's root never reaches the host file system or host git, even when the process backend made it a real host path (J1 test `the host never reads a box project`).
2. A Files, Changes or knowledge call on a stopped box answers `box_stopped` at once and never starts the VM; the `vcs` poll skips stopped boxes (B3 and B4 tests).
3. A session or trigger with a cwd under a box root is created without `realpath` and lands in that project; a cwd that only looks like a box root (`/boxes/<uuid>/project/../x`, a different uuid, `/boxes/<uuid>/projectX`) is refused or treated as a host path, never routed to the wrong box (B2 tests).
4. "Allow this host" on a box session adds exactly that host to that project's list (audited), never to the owner's list or another project's; a host session cannot call `network.request` (A7 tests).
5. Deleting a project with a running session and a running task stops both, removes its rows and triggers, and moves the disk and mirrors to the trash; Scratch with sessions refuses (B1 and J1 tests).
