# Boxes lot B2 (the terminal and GitHub in a box) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A box project gets its own terminal inside the VM, and the complete GitHub integration:
- a pap GitHub App;
- projects created by clone or fork;
- per-box, one-hour tokens;
- a signing key per project;
- commit, push and PR from the box;
- a GitHub tab with PRs, checks, failed-check logs, issues and releases.

**Architecture:**
- **S1** writes the shared contracts:
  - new guest ops and their timeouts;
  - the pty frames and the `terminal` hello role (protocol 3);
  - the GitHub views and RPCs;
  - `github_unavailable`;
  - a loopback fake GitHub for tests.
- **Lane A** covers the VM side and the web:
  - the guest pty and node-pty in the base image;
  - the daemon's remote pty behind the existing terminal module;
  - the guest's GitHub ops;
  - every web screen.
- **Lane B** covers the daemon's GitHub module:
  - App secrets, the API client, the state store and tokens;
  - the App creation and authorization routes;
  - projects from GitHub, token delivery and signing keys;
  - push and PR, lists, logs and "send to a session".
- **Join:**
  - wiring and journeys on the process backend with the fake GitHub;
  - ADR 0084;
  - one Opus final review;
  - the root window.

**Tech Stack:** TypeScript (erasable), Node 24, zod, vitest, node-pty, SQLite migrations, React, the box stack from B1 (pap-vmd, the gateway, the guest, guest ops).

**Spec:** `docs/specs/2026-10-24-boxes-b2-design.md`; decisions 124 to 126. The decisions form is `docs/research/boxes-b2-m14-decisions.html`, where every recommendation was accepted. Recon (exact paths and line numbers) is the planning session's `b2-recon.md`. Copy it into the SDD workspace as `recon.md`.

## Global Constraints

**Repo rules (AGENTS.md, CI-enforced):**
- 400 lines per file at most, tests included.
- Module boundaries: a daemon module imports only `@pap/contracts`, `kernel/` and other modules' `index.ts`.
- Every RPC declares a permission, an idempotent flag and its errors. Handlers decode, call one service method and map typed errors.
- The UI uses tokens only.
- The only ESLint directive allowed is `eslint-disable-next-line <rule> -- <reason>`.
- Erasable TS only. Relative imports keep `.ts`. Timers go through the kernel `Clock`.

**Test isolation:**
- Tests never touch `~/.pi/agent`, `~/.pap` or `~/.claude`.
- Tests never contact github.com, api.github.com or any public host. Every GitHub call in a test goes to the fake GitHub on loopback, reached through `PAP_TEST_GITHUB_ORIGIN`. That variable is for tests only, needs `PAP_TEST_PROVIDER_SCRIPT`, and stops the boot without it.
- Tests never reach the real pap-vmd (`/run/pap-vm/vmd.sock`), `/opt/pap-vm` or `10.213.0.1`.
- A vitest run of a directory always passes `--project unit` or `--project integration`. Without it, `*.kata.int` files run.

**Box paths and identity:**
- The project folder is `/boxes/<id>/project`. HOME is `/boxes/<id>/home`.
- The token file is `/run/pap-github/token` in the guest (tmpfs, 0600). The signing key is `home/.ssh/pap_signing` (ed25519).
- git identity:
  - `user.name` = the GitHub login;
  - `user.email` = `<id>+<login>@users.noreply.github.com`;
  - `gpg.format ssh`, `user.signingkey <home>/.ssh/pap_signing.pub`, `commit.gpgsign true`.
- A key is named on GitHub `pap <project name> <first 8 of the project id>`.

**GitHub App:**
- Manifest:
  - name `pap-<host label>-<4 hex>`, `public: false`, webhooks off (`hook_attributes.active: false`);
  - `redirect_url` = `<origin>/github/app/created`, `callback_urls: ["<origin>/github/app/authorized"]`, `request_oauth_on_install: true`;
  - repository permissions: `contents: write`, `pull_requests: write`, `issues: read`, `checks: read`, `actions: read`, `metadata: read`, `administration: write`.
- Box tokens request `{contents: write, pull_requests: write}` only. List tokens request read scopes only.
- The callback `state` is random (32 hex), single-use, valid ten minutes, bound to the starting user.

**Secrets:**
- The App file is `$PAP_HOME/secrets/github-app.json`: 0600, opened with O_NOFOLLOW, at most 16 KiB, written with `writePrivateFile`.
- The user token and refresh token go in the vault's user scope (`{kind: "user"}`), under the names `github.user_token` and `github.refresh_token`.
- These values never reach a log, an audit row or a response. Add them to the owner-secrets collector so value redaction knows them.

**Timings and limits:**
- The box token is renewed every 45 minutes while the box runs.
- User-token refreshes are single-flight, and the new pair is written to the vault before it is used.
- Lists are cached 60 s, 50 items each, releases the latest 20.
- A check log shows the last 64 KiB.
- The pty window is 1 MiB of unacknowledged output. A pty output frame carries at most 64 KiB raw.
- Guest op timeouts: `git.clone` 600 s, `git.push` 120 s, `gh.prCreate` 60 s; every other op 30 s.

**Protocol:** `AGENT_VM_PROTOCOL` goes from 2 to 3 (new `terminal` hello role and new ops), so a `sudo pap vm setup` is needed.

**Permissions:**
- `github.status`: `settings:read`.
- `github.startCreate`, `github.authorizeUrl`, `github.disconnect`: `settings:admin`.
- `github.forget`: `settings:admin` with step-up.
- `github.repositories`: `sessions:operate`.
- `projects.createFromGithub`, `projects.linkGithub`, `projects.unlinkGithub`, `projects.cloneAgain`, `projects.commitPush`, `projects.prCreate`, `projects.sendToSession`: `sessions:operate`.
- `projects.github` and `projects.checkLog`: `sessions:read`, and a token may call them.
- Browser only (a token caller gets `forbidden`): everything except `github.status`, `projects.github` and `projects.checkLog`.

## Review Focus

1. A GitHub secret (App key, client secret, user token, refresh token, a box token) never appears in a log line, an audit row, an RPC answer, a page the daemon serves or the guest's disk. Box tokens live in `/run` only. Tests B1 `secrets never leave` and J1 `no secret in logs`.
2. A callback with a reused, expired or foreign `state`, or without one, is refused and changes nothing. Tests B2.
3. A box token reaches only the project's repository, never with `administration`. A fork's PR never calls the upstream's API. Tests B3 and B4.
4. A terminal left detached and silent lets the box idle out. Closing a box ends its terminals cleanly. Tests A2.
5. Text from GitHub is never rendered as HTML and always reaches a session fenced, tainting it. Tests B4 and A4.

  - errors mapped to `github_unavailable`, `not_found`, `conflict`, `capacity` (rate limit) and `forbidden` (missing permission).
- **`jwt.ts`:** RS256 with `node:crypto`; iat −60 s, exp +9 min.
- **`tokens.ts`:**
  - `installationFor(repo)` uses GitHub's per-repository lookup and is cached;
  - `mint(repo, permissions)` answers `{token, expiresAt}` and refuses any permission outside the asked set.
- **`user-tokens.ts`:**
  - `get()` refreshes single-flight before expiry and writes the vault before returning;
  - a failed or expired refresh puts the state in `reconnect` and answers `github_unavailable`.
- **`states.ts`:** random 32 hex, single-use, ten minutes on the Clock, bound to the user id.
- **Owner-secrets collector:** add the App key, the client secret and the user tokens.

**Interfaces:** consumes S1 and the fake GitHub. Produces `createGithubModule(deps)` with `tokens`, `userTokens`, `client`, `states`, `appSecrets` (internal), exported through `index.ts` for J1.

### Task B2: App creation and authorization

**Files:** `modules/github/http.ts`, `service.ts`, `rpc.ts`, plus tests. Mount them through `modules/github/index.ts` (J1 adds one line in `daemon.ts`).

- **`GET /github/app/new?state=`:**
  - cookie auth, `settings:admin`;
  - a state from `github.startCreate`;
  - it serves a minimal page with its own CSP (`form-action <github web origin>`), which auto-posts the manifest from Global Constraints to `<github web>/settings/apps/new?state=`.
- **`GET /github/app/created?code&state`:**

### Task B3: projects from GitHub, tokens to the box, signing keys

**Files:** `modules/github/projects*.ts`, `deliver.ts`, `keys.ts`; a migration `modules/projects/migrations/<stamp>_project_github.sql`, `CREATE TABLE project_github(project_id PRIMARY KEY, repository, upstream, fork INTEGER, key_id, key_state, clone_state, clone_error) STRICT`; thin edits in `modules/projects` through its index.

- **`github.repositories`:** lists the repositories of every installation the owner can access (organisations included), filtered by `query`, at most 100.
- **Clone failures:** a failed `git.clone` sets `clone_state: failed` and `clone_error` (a fixed word: `auth`, `network`, `not_found`, `failed`). `ProjectGithubView` carries both, so the web shows the notice. `cloneAgain` resets them and retries.

- **`projects.createFromGithub`:**
  - Clone: creates the box project (B1's `make()`) with the GitHub row and seeds GitHub's hosts (Global Constraints) on its list.
  - Fork: forks with the user token first, then polls `GET /repos/{fork}` every 2 s for 60 s at most on the Clock (then `github_unavailable` with a clear detail), then the same as Clone.
- **`linkGithub` / `unlinkGithub` / `cloneAgain`.**
- **Delivery on `BoxControl.onPhase(running)`** for a GitHub project:
  - mints a box token, sends `github.token`;
  - sends `github.identity` (login, name, noreply email);
  - uploads the returned key if it has none (403 → `permissionMissing`);
  - sends `git.clone` when `project/` is empty and the row is new;
  - renews the token every 45 minutes while running.
- **Deleting or unlinking:** removes the key from GitHub. A failure keeps `key_state: failed`, and the daily sweep retries it.
- **Box tokens:** `{contents: write, pull_requests: write}` only.

**Interfaces:** consumes B1 and B2, the B1 lot's `BoxControl`, `BoxOps`, and the projects port. Produces the project RPCs, the delivery loop and `project_github` rows.
