**Goal:** make v1.0.0 releasable. (1) The fifteen e2e journeys of spec C §8.1 run on Chromium and WebKit with one command. (2) Spec A success criteria 1 to 4 each have evidence in the repository. **Architecture:**
- **E2E is a script-level suite**, not a workspace package: `scripts/e2e/` holds the Playwright config, one fixture layer that boots the **built** daemon exactly like `pnpm smoke` does (it imports `scripts/smoke-lib.ts`: `startDaemon`, `freePort`, the network guard), the journeys (`jNN-*.e2e.ts`, so Vitest never collects them) and the runner `pnpm test:e2e`. The runner uses local browsers when both exist; otherwise it starts the pinned Playwright image with rootless podman (`run-server`, `--network host`) and the tests connect to it with `connectOptions`. Journeys select by role and accessible name, taking the text from the web app's own English catalog, so copy changes do not break them and no raw string is duplicated.
- **The enforcement is in tests, not in prose.** The security-test index, the docs-truth checker and the parity table each have a unit test that fails when a referenced file, test title, path, env variable or RPC method no longer exists.
- **Release steps are the owner's.** The plan changes files; it never publishes, tags, renames the repository's visibility, picks a licence or touches the live units. Those are the controller runbook (Part 2) and the owner runbook (Part 3).

**Tech Stack:** Node 24 (erasable TypeScript), Vitest, `@playwright/test` 1.63.0, bash, GNU tar, rootless podman, `yaml` 2.9.1 (already a devDependency), the existing smoke and test beds.

## Review Focus

Failure modes that no task's own tests would catch and that are most likely to bite a person using the result, most likely first. Each line has its test in the owning task.

1. **A journey that passes while testing nothing** (a locator that matches a hidden duplicate, an assertion on a spinner). Every journey ends with an assertion on durable state read from outside the page (a file on disk, a row through RPC, a journal line), not only on the DOM. Owner: A2 to A5, one mutation per journey (break the app behaviour, see the journey fail).
2. **`pnpm test:e2e` silently running zero tests or the wrong browser** (a wrong grep, a missing project). The runner fails when the list is empty or a project has no tests; it prints the browser name and version of each project. Owner: A1.
3. **A stranger reads a docs claim that is false** (a path, an env variable or an RPC method that does not exist). The docs-truth test fails the gate. Owner: C1, P1, P2.
4. **The live outside-write warning shows for pap's own writes** (a false alarm every turn) or never shows. Owner: B2: a clock-driven test with pap's own append inside the grace, one after it, and a second app's append.
5. **The shrinkwrap pins a version the lockfile does not** or drops an integrity hash, so a stranger installs different code than CI tested. Owner: B6: round trip against the lockfile for every entry, one mutation per field.
6. **Pi-compat tests a release younger than the rule allows** (clock skew, a missing `time` entry, a pre-release picked as newest). Owner: B5.
7. **Cutover docs that tell the owner to run a command that does not exist, or that move the live data.** Every command in `docs/agents/cutover.md` is copied from a test or a help text (the C5 test checks it against `pap --help` and the service flags). Owner: C5.

## Plan rulings (M13R1 to M13R34)

**E2E**
- **M13R1** E2E lives in `scripts/e2e/`; journeys are `jNN-name.e2e.ts`; Playwright 1.63.0 exact as a root devDependency. Why: no new workspace package, no boundary-lint element to add, the smoke code is next door and reusable. Cost: `scripts/` grows by about 2 000 lines of test code; every file stays under 400.
- **M13R2** `pnpm test:e2e` = `node scripts/e2e/run.ts`. Mode `local` when `chromium` and `webkit` executables both exist; otherwise mode `container` (podman image `mcr.microsoft.com/playwright:v<installed version>-noble`, `run-server --host 127.0.0.1 --port <free>`, `--network host`, the repo's `playwright-core` folder mounted read-only at `/pw`); `PAP_E2E_MODE=local|container` forces one; with neither it exits 1 with the sentence "no browser and no podman: see docs/agents/e2e.md". The image tag is derived from the installed version, and a test pins it. Why: the host is headless with no sudo (proven by the controller harness); CI installs browsers itself once the repository is public.
- **M13R3** Every spec file boots its own built daemon on a free port (`startDaemon`, network guard, scripted provider, `PAP_WORKER_SCOPE=off`, `PAP_MIN_FREE_DISK_MB=0`, `PI_OFFLINE=1`), with its own script. Why: one daemon holds one script file and each worker walks it from the start (smoke-lanes). Cost: 3 to 5 s per spec file.
- **M13R4** Locators are `getByRole`/`getByLabel`/`getByText` with text taken from the English catalog through `t(key)` (`scripts/e2e/catalog.ts` imports `apps/web/src/i18n/catalog/*.ts`). No CSS or test-id selectors, no `waitForTimeout`. Why: copy and markup change; the catalog is the contract.
- **M13R5** Passkey: the Chromium project drives WebAuthn with a CDP virtual authenticator (`WebAuthn.enable`, `addVirtualAuthenticator` ctap2 internal, resident keys, user verification). **WebKit has no virtual authenticator: its J01 runs the password path** and the passkey half is `test.skip(browserName === "webkit", "no virtual authenticator in WebKit")`.
- **M13R6** All journeys run on both browsers except the passkey half of J01 and J13 (push enable: Chromium only, stubbed subscription). The skip reason is in the code and in `docs/agents/e2e.md`.
- **M13R7** E2E is a gate step at **J1 and the final review only**, plus the CI job. Not in a task gate, not in a fix-round gate. Runtime budget: 10 minutes in the container for the whole suite; a journey over 60 s is a defect.
- **M13R8** The controller runs the journeys in the container after each A task (CE1 to CE5) and hands failures back as fix rounds. An implementer never claims a journey passes; the report says "listed and typechecked, not run".
- **M13R8b** The push journey uses a stubbed `PushManager` and a loopback sink under `PAP_TEST_PUSH_LOOPBACK=1`; nothing reaches a real push service.

**Compatibility, budgets, security**
- **M13R9** Pi-compat = "the newest release of `@earendil-works/pi-coding-agent`, `pi-ai` and `pi-tui` that exists for all three at the same version and is at least `minimumReleaseAge` old", written as an exact version in the catalog before install (no `latest`, no age override). `pnpm pi-compat` runs it locally on demand and restores `pnpm-workspace.yaml` and the lockfile on exit; the nightly workflow does the same once the repository is public. Why: the rule is a supply-chain control; the cost is that a release is tested 3 days late. Today it would test 1.2.0.
- **M13R10** Final budgets are the table above. The deterministic ones (bundle, SW, payload, RSS) get a 7 to 11 % margin over the measure, except the payload (a ten-exchange snapshot is 9.5 KB; 24 KB leaves room for a real session's preview rows). The two timing budgets keep 50 to 90 % because CI hosts are slower. `pnpm budgets` asserts all six keys exist and are named by an enforcing test; `test:budget` joins the CI `budgets` job (about 2.5 minutes). Cost if wrong: a CI flake on a slow host; the fix is one number.
- **M13R11** The ten security rows above are indexed in `docs/agents/policy.md` ("Security tests") as spec item, file, test title; `scripts/security-index.test.ts` fails when a file or a title is missing.
- **M13R12** Crash-isolation additions are integration tests in `apps/daemon/src/modules/sessions/` (`sessions.crash.hard.int.test.ts`), run in the existing int project.
- **M13R13** Spec D §3 for a live worker: while a pap worker is live, a change to its Pi file that appears more than `LIVE_GRACE_MS` (10 000) after the worker's last event and while it is idle counts as written outside pap. It sets `outsideWrite` (the existing snapshot field and banner). **It does not taint**: taint on outside tool results is already decided for released sessions (M7R27) and a live worker never reads the file again. Cost if wrong: a banner for two minutes that is not needed; no data effect.
- **M13R14** The egress proxy, push and the feed guard share one strict address predicate: `blockedStrict` (rename of `blockedForPush`, same behaviour) in `kernel/net/address-strict.ts`. `blockedAddress` stays as the base it extends.
- **M13R15** The shrinkwrap is generated **offline** from `pnpm-lock.yaml` by `scripts/npm-shrinkwrap.ts` (production closure of `apps/daemon`, `packages/contracts`, `packages/pi-host`; npm lockfile v3; every entry has `version`, `resolved`, `integrity`; `@pap/*` entries are `inBundle`). `pnpm build:npm` writes it into the package; `pnpm release:check` refuses a package without it or with an entry that differs from the lockfile. The controller verifies once, with the network, that `npm install --package-lock-only --ignore-scripts` on the staged package changes nothing (step CB6). Why: npm resolves floating transitive ranges otherwise (Appendix A defect D3).
