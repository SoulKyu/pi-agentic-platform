Automation et outbox

On garde tous les déclencheurs et garde-fous de pi-web : planification, webhooks, flux RSS/Atom, budget, heures calmes, garde de run. Ce qui change, c'est la mécanique. Les fichiers JSON de tâches et leurs verrous de claim sont remplacés par une seule transaction SQLite, qui écrit en une fois le tir, la tâche et l'effet à exécuter. Après un crash, chaque effet sait s'il peut être rejoué ou non.

2 · L'outbox

  • Table outbox : kind, payload, status, attempts, next_at, lease_until, replay.
  • Règle unique : un changement d'état et l'effet qu'il implique sont écrits dans la même transaction. Il n'y a jamais d'effet sans état, ni d'état sans effet.
  • Un seul worker dans le daemon. Bail de 30 s, 5 tentatives avec backoff, puis l'effet passe en failed, visible dans Santé. Les effets réglés sont purgés après 7 jours.
  • Chaque effet est classé : replay-safe (rejoué après un crash) ou process-bound (retiré après un crash, jamais rejoué). Classification reprise de T3.

3 · Démarrage du daemon : la récupération d'abord

1 · Récupération

Les tâches encore running passent en interrupted. Les effets process-bound sous bail sont retirés, les effets replay-safe remis en file. Rien d'autre ne démarre avant la fin de cette étape (règle T3 « parked roots »).

2 · Pas de rejeu automatique d'un run

Une tâche interrompue n'est pas relancée par défaut, car un run peut avoir déjà poussé, posté ou écrit. Le trigger peut l'activer (retryOnInterrupt). Sinon, bouton « Relancer » sur la carte.

3 · Tirs manqués

Si le daemon était arrêté à l'heure d'un tir planifié, par défaut il est sauté et noté « missed » dans le journal (T3 : jamais de tir en retard). Option par trigger : catchUp: once, qui rattrape un seul tir dans une fenêtre de grâce (Orca).

4 · Détails par source

Webhook
  • Secret dans un en-tête, comparé en temps constant (pi-web). Option HMAC-SHA256 sur le corps brut (T3).
  • 64 Ko maximum, lus en flux. Mapping Alertmanager / Grafana vers une ligne par alerte, et dédup sur les empreintes.
  • Réponses : 202 {taskId}, 409 {reason}, 429. Les requêtes non authentifiées sont comptées, jamais journalisées en détail.
Precheck nouveau
  • Commande lancée avant le tir, dans le home de l'agent, sous sandbox, avec 30 s maximum.
  • Code 0 : on tire. Code 1 : on saute, avec la raison notée. Autre code : erreur.
  • Sa sortie, plafonnée à 4 Ko, peut être injectée dans le prompt, clôturée comme non fiable.
  • Les sauts identiques consécutifs sont regroupés dans le journal (Orca), qui reste lisible.
Feed & quota
  • Feed : https seulement, redirections vérifiées, 10 s, 1 Mio, et au plus 10 entrées nouvelles clôturées par tâche (pi-web).
  • Quota provider atteint (usage_limit avec heure de reset) : le run passe en « limited », puis un effet run.resume est planifié à l'heure de reset (T3). Annulable.
  • Heures calmes : les runs tournent, les push sont regroupés dans le digest de fin (pi-web).
