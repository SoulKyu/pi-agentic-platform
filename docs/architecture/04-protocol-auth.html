Spec C · Architecture · Section 4 / 9

Protocole client et auth

Un seul WebSocket porte tout le domaine : requêtes typées et flux avec reprise par curseur. HTTP ne sert que ce qui doit rester HTTP : assets, auth, uploads, webhooks, métriques. Chaque méthode déclare sa permission dans les contrats, et un oubli est une erreur de type.

1 · Contrats : une méthode = une déclaration

// packages/contracts/src/rpc/sessions.ts
export const prompt = defineMethod({
  name: 'sessions.prompt',
  permission: 'sessions:operate',   // obligatoire
  idempotent: true,                    // commandId requis
  params: z.object({
    sessionId: SessionId,
    message: z.string().max(120_000),
    images: z.array(ImageRef).max(20).optional(),
    behavior: z.enum(['steer', 'followUp']).optional(),
  }),
  result: z.object({ runId: RunId, disposition: Disposition }),
  errors: ['session_not_found', 'capacity_reached', 'busy'],
});

// apps/daemon : Record<MethodName, Handler>
// méthode sans handler / sans permission = erreur de compilation
  • zod est la seule source du schéma. Le client a un proxy typé (rpc.sessions.prompt(…)), le serveur une table de handlers exhaustive.
  • Un handler décode, appelle une seule méthode de service et mappe une erreur typée. Une exception ne fait échouer que sa propre requête, jamais le socket (règle T3 disableFatalDefects).
  • Les mutations portent un commandId généré par le client. La table receipts renvoie le même résultat en cas de doublon, sans rejouer d'effet de bord. Une mutation n'est jamais rejouée automatiquement à la reconnexion.
  • Les erreurs ont un code stable et un message fixe, sans contenu utilisateur ni secret dans le message (règle T3).

Reprise (curseur)
  • Le client envoie after = dernier seq vu. Si l'écart fait au plus 128 événements et 1 MiB, il est rejoué. Sinon, snapshot.
  • Le snapshot est borné : environ 75 dernières lignes, le message partiel en cours et les dialogues en attente. L'historique plus ancien se charge par pages (sessions.history{before}).
  • Deltas regroupés toutes les 50 ms. Les gros outputs d'outils ne passent pas dans le flux : on les charge à la demande (sessions.toolOutput).

Superviseur de connexion (client)
  • Un seul propriétaire des retries. Backoff exponentiel avec jitter plafonné à 30 s, remis à zéro après une connexion stable.
  • Au retour au premier plan ou quand le réseau revient : on sonde la session avant de reconnecter. Les événements « offline » sont souvent faux, surtout sur iOS.
  • État et curseur sont gardés 5 min en mémoire. Au-delà, snapshot.

3 · Auth (décision 10)

1 · premier démarrageLe daemon affiche dans son log une URL de setup à usage unique (jeton aléatoire). Personne d'autre sur le réseau ne peut s'approprier l'instance.
2 · compte ownerMot de passe (crypto.scrypt de Node) et passkey WebAuthn (@simplewebauthn/server). Le passkey devient la connexion par défaut.
3 · session navigateurCookie HttpOnly, Secure, SameSite=Strict, id opaque stocké haché. Durée 30 jours glissants, révocable dans « Appareils connectés ».
4 · autres appelantsJetons API pap_… hachés, avec permissions et expiration, pour le CLI et les scripts. Webhooks : secret par trigger (+ HMAC optionnel). /metrics : bearer dédié.
Permissions
  • Format domaine:read|operate|admin (sessions, lanes, agents, automation, settings, security…).
  • v1 : l'owner a tout. Un jeton API reçoit un sous-ensemble. Les futurs rôles d'équipe ne seront que des ensembles de permissions, donc pas de refonte.
  • L'identité de l'appelant est fixée par le transport, jamais lue dans les paramètres (Orca).
Défenses
  • Contrôle de l'Origin à l'upgrade WS et sur chaque POST, en plus de SameSite=Strict, contre le CSRF.
  • Throttle des tentatives de login par IP et par compte, avec backoff (pi-web auth-throttle).
  • Les en-têtes X-Forwarded-* ne sont pris en compte que si trustProxy est configuré.
Exposition réseau
  • Écoute sur 127.0.0.1 par défaut. --host 0.0.0.0 doit être explicite.
  • Les passkeys, la PWA et Web Push exigent HTTPS (sauf localhost). Accès distant via Tailscale serve ou un reverse proxy (Caddy, Traefik), documenté. Option --tls-cert/--tls-key pour fournir son propre certificat.
  • Pas d'ACME intégré en v1 : le proxy ou Tailscale le fait mieux.

Choix techniques : Hono + @hono/node-server pour la dizaine de routes HTTP (aucune dépendance transitive ; serveStatic, secureHeaders et cookies testés ; tests de routes en mémoire via app.request()), ws pour le WebSocket (l'upgrade reste hors de Hono), zod pour les contrats, @simplewebauthn/server pour WebAuthn. On ne réimplémente pas de crypto.
