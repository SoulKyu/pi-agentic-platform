Tests et quality gates

Contre l'étalement du code, le levier est une CI qui refuse ce qui déborde, dès le premier commit. Contre la fragilité, ce sont des tests qui font tourner le vrai pipeline (SDK Pi, extensions, politiques, SQLite, git) avec un seul faux : le modèle. Pas de sleep dans les tests, pas d'objectif de couverture en pourcentage.

1 · Les niveaux de tests

Unitaires
Logique pure : évaluation des politiques (tables de cas), RRULE et tirs manqués, mapping Alertmanager / Grafana, masquage, chemins sûrs, view-models du front, décodage tolérant des événements.
Vitest, un seul runner pour daemon, pi-host et web. Rapide, à lancer à chaque sauvegarde.
Intégration daemon
Vraie SQLite temporaire, vrais dépôts git temporaires (pattern lanes de pi-web), vrai pi-host avec le SDK Pi. L'outbox est vidée explicitement (« drain »), l'horloge est injectée par le kernel, aucune attente réelle.
Le cœur de la confiance : session, approbation, lane, trigger, crash du worker, récupération au boot.
E2E navigateur
Playwright contre le daemon construit, sur Chromium + WebKit (le plancher Safari). Environ 15 parcours clés : setup de l'owner, passkey (authenticator virtuel), prompt → approbation → résultat, lane → commit → PR (gh simulé), webhook → run → inbox, reprise après coupure, viewport mobile.
Repris de e2e/run.mjs de pi-web, élargi à WebKit.
Compat Pi nouveau
Job nocturne qui rejoue la suite d'intégration contre la dernière version du SDK Pi (on livre une version épinglée). Une casse amont est repérée avant la mise à jour, pas après.
Pattern Orca pi-provider-runtime.yml.
Le seul faux : un provider scripté

Les tests enregistrent dans pi-host un provider Pi scripté (via l'API custom provider de Pi, docs/custom-provider.md). Il renvoie des réponses écrites d'avance : du texte, des appels d'outils, des erreurs de quota. Tout le reste est réel : SDK, extensions, pap-policy, bash dans bwrap, SQLite, git. Aucun appel réseau, aucun coût de tokens, résultats déterministes.

plus fort que T3, qui rejoue des transcripts RPC au niveau de l'adaptateur · à valider au spike
Tests ciblés sécurité
  • Path traversal sur /files et sur le service statique.
  • Webhook : mauvais secret, HMAC faux, corps de 64 Ko + 1, rejeu de la clé de dédup.
  • Fail closed : une règle de politique invalide ou une exception doit donner un block.
  • Contamination : contenu externe, puis tentative d'exfiltration, doit déclencher une demande.
  • Origin falsifié à l'upgrade WS, cookie sans SameSite.

2 · Quality gates (CI, toutes bloquantes)

400 lignes / fichier

ESLint max-lines, sans baseline ni exception. Un fichier qui déborde se découpe.

Frontières de modules

eslint-plugin-boundaries : un module n'importe que contracts, kernel et l'index.ts d'un autre module.

Code mort

knip : fichiers, exports et dépendances inutilisés font échouer la CI (T3).

Désactivation motivée

Tout eslint-disable doit porter une raison (règle require-description).

Typecheck

tsc --noEmit strict sur tout le monorepo. Les permissions RPC exhaustives sont vérifiées ici.

Design system

Lint : pas de couleur brute, pas de valeur arbitraire, pas de restyle de primitive (T3).

Budgets

Bundle initial, payload d'ouverture de session, mémoire d'un worker idle. Mesurés et comparés à un seuil.

Supply chain

pnpm : versions épinglées, minimumReleaseAge de 3 jours (Orca), allowlist des builds natifs (node-pty), Renovate.

4 · Un repo vivable pour les humains et les agents

Isolation du dev nouveau

pap serve --dev utilise un PAP_HOME propre au worktree et un port dérivé de son chemin (T3). Plusieurs worktrees et agents peuvent tourner en parallèle sans se marcher dessus. C'est la fin des conflits de type .next/dev/lock de pi-web.

AGENTS.md court

Au plus 150 lignes : commandes, règles, liens. Pas de carte de fichiers géante comme celle de pi-web : la structure est prévisible, puisque chaque domaine a son module. Les notes de conception restent dans docs/agents/<domaine>.md (pattern pi-web qui marche).

Conventions
  • Conventional Commits, rebase sur la cible avant chaque PR (ta règle globale).
  • ADR courts dans docs/adr/ pour chaque écart avec la spec.
  • Prettier pour le format. Pas de pre-commit lourd : formatage seulement (T3).
