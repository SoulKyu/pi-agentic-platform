# UX-2: previews of what an agent serves, and rich replies

Status: approved by the owner (decision 138) · Date: 2026-10-28 · Lot UX-2 of the UX review (owner, 2026-10-28). ADR 0088 records the lifted non-goal.

Owner's example: "help me get better at <topic>, build a Python HTTP site that follows my training on it". The agent can write the site today, but the owner cannot see it. Its replies cannot show a diagram, a formula or an image either.

## 1. Intent

- **Previews.** An agent, or a session in a box, can start a small web server in its VM and hand the owner a preview. The owner opens it in one click, inside pap, without exposing pap to what the server sends.
- **Rich replies.** Replies can show Mermaid diagrams, math, images from the box's own files, and HTML artifacts.

Spec A §6 lists "embedded browser or preview" as a non-goal. This lot lifts it for **previews of what an agent serves from its own VM**. It is not a general browser. ADR 0088 records it.

## 2. Two facts from the code that shape the design

- **Background processes die.** The VM shell runs every command in bwrap with `--unshare-pid --die-with-parent` (`packages/pi-host/src/vm-shell/argv.ts:59-64`). `python -m http.server &` is killed when the command returns. A preview needs a **supervised service**, not a shell job.
- **A shell without network has its own loopback.** With the network off, the shell runs with `--unshare-net` (`argv.ts:60`). A server started there listens on a loopback that nothing else in the VM reaches.

## 3. Goals

- **G1. Supervised services.** A session in a box or an agent thread starts a named service, a command plus a port, that keeps running after the call returns. Its confinement is the session shell's: bwrap, seccomp, read-only image root, and the session's network setting. The owner sees it, its logs, and can stop or restart it.
- **G2. Open a preview.** A card in the chat, and the box's or agent's page, offer OPEN PREVIEW. The site shows in a Preview pane beside the chat, on a separate untrusted origin.
- **G3. The project file can declare a preview.** `.pi/project.yaml` gets `preview: {command, port}`, started by a button on the project page.
- **G4. Rich replies.**
  - Mermaid fences render as diagrams.
  - `$…$` and `$$…$$` render as math.
  - `![alt](relative/path)` renders an image from the session's own files.
  - An `html` fence offers a sandboxed rendering.

**Non-goals:**
- a general browser, or previews of external sites;
- sharing a preview with someone outside pap (a share link comes later, if ever);
- previews for host projects, lanes, isolated tasks or children (lanes come with B3);
- starting a service at box start by itself;
- protocols other than HTTP/1.1 and WebSocket over it;
- remote images in replies (a remote URL stays a link, never loaded).

**Anti-goals:**
- content from an agent running with pap's origin, cookies, storage or service worker;
- a preview that reaches the network its session could not reach;
- a preview that keeps a box running after the owner closed it;
- a capability URL in a log, an audit row or a `Referer`;
- a framed page that can pass for pap's own UI without the untrusted frame around it.

## 4. The untrusted origin (shared by previews and HTML artifacts)

- **A second listener.**
  - The daemon serves untrusted content on its own port: `--preview-port`, `PAP_PREVIEW_PORT`, default the main port plus one (7778).
  - It binds the same host as the app and uses the same TLS settings.
  - Its public origin defaults to the app's origin with that port. `PAP_PREVIEW_ORIGIN` overrides it for reverse proxies: an `https://` origin, or `http://` to loopback or with `--insecure-http`, the same rule as the app.
  - The app's CSP gains `frame-src <preview origin>` and nothing else.
- **Capability URLs.**
  - Every path starts with a token: `/p/<token>/` for a service, `/a/<token>/` for an artifact. Each token is 32 random bytes in base64url.
  - A token is a **bearer** capability: the page can read its own address, and a service with network can send it out. Its reach is to view and use that one service or artifact, nothing else in pap.
  - Tokens are minted only by the browser of the box's owner, through an RPC with a command id. The box's owner is the project's or agent's owner, the owner and members alike, and only for their own boxes. API tokens get `forbidden`.
  - Lifetime:
    - An artifact token dies after 1 hour.
    - A service token dies when the service stops or its box stops. It is also a lease (§9, decision 6): held while a Preview pane is open on it, renewed every 60 s over the socket, revoked 5 minutes after the last renewal.
  - The listener keeps tokens in memory only, so a daemon restart revokes them all.
  - The listener refuses any other path with a bare 404.
- **Every response on that origin carries:**
  - `Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-downloads; frame-ancestors <app origin>`. The document then has an opaque origin: it gets no cookie, no storage, and sends `Origin: null`.
  - `Referrer-Policy: no-referrer`.
  - `Cache-Control: no-store`.
  - `X-Content-Type-Options: nosniff`.
- **Requests and responses are cleaned.**
  - The listener drops the request's `Cookie` and `Authorization` headers before relaying, so pap's own cookie never reaches the VM.
  - It drops `Set-Cookie` from what the VM answers.
  - It never follows a redirect. A redirect is relayed with its `Location` rewritten only when it points inside the same preview.
- **The price of that isolation** (owner decision 1, §9): an app under a path prefix must use relative URLs.
  - The listener sends `X-Forwarded-Prefix: /p/<token>`, which several frameworks read.
  - The op's description tells the agent to use relative links.
  - Cookie-based logins do not work inside a preview.
- **CORS, because the document's origin is opaque** *(controller's call; without it the owner's example breaks)*. An opaque origin makes the page's `fetch`, XHR, module scripts and web fonts cross-origin requests to its own server.
  - The listener adds `Access-Control-Allow-Origin: *` to every response it relays and never adds `Allow-Credentials`.
  - It relays an `OPTIONS` preflight to the app. If the app's answer lacks CORS headers, the listener answers 204 with the requested method and headers allowed.
  - That is safe because there is no credential, only the capability URL.
- **pap refuses same-site requests** *(controller's call)*. SameSite ignores ports, so the preview origin is same-site with pap.
  - Every daemon route refuses a request whose `Sec-Fetch-Site` is `same-site` or `cross-site` with 403, logged `fetch_site_refused` and rate-limited. The exceptions:
    - a top-level navigation (`Sec-Fetch-Mode: navigate`) to the app shell;
    - `/hooks/*`;
    - the GitHub callbacks.
  - A request without the header (an older browser, a program) keeps today's checks: the Origin guard, SameSite=Strict cookies, and the WebSocket `Origin` rule.
  - An e2e test proves that a preview page can neither read `/files/raw`, nor open the WebSocket, nor post to a route, in Chromium and WebKit.
- **Bounds.**
  - 32 open connections per box.
  - Request bodies up to 10 MiB.
  - Responses are streamed, with no size cap: the byte count is logged.
  - 120 s idle per connection.
  - Every refusal is logged once per token per minute, with the token redacted.

## 5. Supervised services (guest)

- **The op.** A new platform op, `preview.start {name, command, port}`. Its answer is the service id and status; it never returns a URL.
  - Callers: `agent-thread` and `plain` sessions of a box.
  - `whenTainted: "run"`. The content is sandboxed and labelled, and the owner opens it with a click.
  - Deadline: 60 s, which covers the port check below.
  - Companions: `preview.stop {name}`, and the owner's RPC methods `previews.list | stop | restart | logs | open` (`open` mints the token).
- **The guest's supervisor.**
  - The guest runs the command in bwrap with the session shell's own argv: same binds, seccomp and capabilities, and the session's network setting. The difference is that the guest keeps it running after the call.
  - It waits up to 30 s for the port to accept a connection, then reports `running`. Otherwise it reports `failed` with the log tail.
  - **Port ownership** *(controller's call)*. `running` needs the listening socket to belong to the service's own process tree: its socket inode is checked against the fds of the processes the service runs.
    - Another listener in the VM (Pi, an MCP server, another service) gives `failed` with reason `port_not_owned`.
    - The tunnel dials only a port its service owns, checked again before each connection.
  - It keeps the last 200 lines of output, 512 characters each, which are redacted by the worker's value redactor before they leave the VM.
  - It restarts nothing by itself.
- **Limits.**
  - 4 services per box.
  - Ports 1024 to 65535, except the bridge ports 7841 to 7843.
  - A name is 1 to 32 characters of `[a-z0-9-]`. Starting a name that already runs restarts it.
- **Lifetime.**
  - A service stops with its box.
  - It counts as activity for the idle stop only while a Preview pane is open on it and traffic flowed in the idle window, the rule terminals follow.
  - The project page and the agent page list a box's services with their state, port, uptime, and the actions STOP, RESTART, LOGS, OPEN PREVIEW.
- **Network.**
  - A service keeps exactly the network its session's shell has.
  - With the network off, the guest reaches the service's port by entering the service's network namespace for the connection, not by widening it. The builder proves which mechanism holds, for example `setns` on the service's `/proc/<pid>/ns/net` from guest root.
  - The proxy rules are unchanged for anything the service itself fetches.
- **The project file.** `.pi/project.yaml` accepts `preview: {command, port}`, parsed by the same strict rules as the file's other keys.
  - The project page shows START PREVIEW when it is present.
  - The guest starts it as the service `project`, with the project profile's network.
  - Nothing starts it automatically (§9, decision 2).

## 6. The tunnel (protocol 4)

- `AGENT_VM_PROTOCOL` becomes 4, with a new hello role, `tunnel`, carrying a slot.
- **Opening a connection.**
  - To relay a connection, the daemon asks the guest over the guest link (`preview.connect {serviceId, slot}`).
  - The guest dials a new gateway connection with role `tunnel`, connects to the service's port, and splices bytes both ways.
  - This mirrors B2's terminal connections and opens no new port and no new firewall rule. A protocol-3 guest is refused, so `sudo pap vm setup` is needed after the update (pre-approved by the owner for this run).
- **Flow control.** Back-pressure works in both directions: the guest stops reading while 1 MiB is unacknowledged, the rule terminals use.

## 7. The Preview pane and the chat card

- **The strip** *(controller's call, replacing a stored card: session notices are live-only and Pi entries are the model's)*. While a service of the session's box runs, a strip above the composer reads "Preview <name> · port <port>" with OPEN PREVIEW.
  - It is derived from the services the daemon reports, so it is never stored in the transcript. It shows in box sessions and agent threads alike.
  - It disappears when the service stops. The model's own reply says what it built.
- **The pane.** A new item kind, `preview`, keyed by service. It shows:
  - the dashed untrusted frame of DESIGN.md §2, labelled `UNTRUSTED · preview <name>`;
  - a toolbar with RELOAD, OPEN IN A NEW TAB, LOGS and STOP;
  - an iframe with `sandbox="allow-scripts allow-forms allow-popups allow-downloads"`, so no `allow-same-origin` and no top navigation, and `referrerpolicy="no-referrer"`.

  The frame label sits outside the iframe and is always visible.
- **Layout.** On a desktop the pane splits beside the chat, with the existing split. On a phone it is a fourth entry, Preview, in the Chat / Review / Term switch, shown only while a service runs.
- **A stopped box or service** shows START (box) or START PREVIEW (service) in the pane. The pane never starts anything by itself.

## 8. Rich replies

- **Mermaid.**
  - Fences tagged `mermaid` render as SVG with Mermaid's `securityLevel: "strict"`, lazily loaded.
  - If the library needs `eval` or inline scripts under the app's CSP, which the builder checks the way `build-output.int.test.ts` checks zod, it renders on the untrusted origin like an artifact instead.
  - A syntax error shows the source with a one-line error.
- **Math.** `$…$` and `$$…$$` render with KaTeX, through remark-math and rehype-katex or an equivalent, lazily loaded, with fonts served as files and no remote font.
- **Images from the session's files.**
  - `![alt](path)` with a relative path, or an absolute path under the session's roots (the same roots as UX-1's links), loads through the existing same-origin raw file route, under the daemon's file rules.
  - It is only ever an `<img>`, never an iframe or an object, so a script in an SVG does not run. Only `.png .jpg .jpeg .gif .webp .svg` up to 10 MiB load. Anything else is a link to the file in Files.
  - The read is the owner's own browser reading a file it could open in Files: no audit row. Taint changes nothing, since nothing leaves the browser.
  - Anything else, URLs included, renders as plain text `[image: alt]`.
  - The "model text never loads a resource" rule now reads "never loads a **remote** resource" (ADR 0088).
- **HTML artifacts.**
  - An `html` fence shows a PREVIEW toggle beside COPY.
  - On click, the browser asks the daemon for an artifact token for that session entry and fence index.
  - The daemon reads the fence from the transcript itself (the Pi file or the mirror), never from the client.
  - The key is `(entryId, fenceIndex)`. A Pi entry never changes once written: an edit or a fork writes new entries, and compaction leaves old ones in the file. A missing entry or index answers `not_found`.
  - The artifact is served on the untrusted origin with a stricter CSP, which leaves it no network at all: `sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:`.
  - It renders inline in a bounded frame (at most 70 % of the viewport's height), with the same untrusted label.
- **Bundle.** Mermaid, KaTeX and the artifact frame are lazy chunks, and `build-output.int.test.ts` gets their markers.

## 9. Owner decisions (2026-10-28, every recommendation, decision 138)

1. **Isolation: A.** Path tokens plus an opaque sandboxed origin: previews have no cookies or storage, and apps use relative URLs.
2. **The project file's preview** starts from a button only, never at box start.
3. **Agents too.** Agent threads get previews, as box sessions do (same guest).
4. **HTML artifacts may run scripts**, with no network at all.
5. **A tainted session may start a preview.** It is sandboxed and labelled, and the owner opens it with a click.
6. **A service link is a lease.** It is held while a Preview pane is open, renewed every 60 s over the socket, and revoked 5 minutes after the last renewal. It also dies when the service or its box stops.

## 9b. Operations *(controller's calls)*

- **Bind failure.** If the second listener cannot bind (port taken, for example), the daemon logs `preview_listener_unavailable` once and runs on without previews. `previews.open` and artifact tokens then answer `unavailable`.
- **Doctor.** `pap doctor` gains a `preview.listener` check: is the port bound, and does it answer 404 on `/`.
- **Install note.** A LAN or reverse-proxy setup must expose the preview port too.
- **Plain HTTP.** `--insecure-http` sends the tokens in clear text, as it already does the cookie. That is accepted for this testing-only mode, with the same warning.
- **Permissions.** `previews.*` take `sessions:operate` for a project box and `agents:operate` for an agent box, checked against the box's owner. `open` is browser only.
- **Down mode.** Without the VM stack there are no services. The Preview pane and the strip are hidden, and the rich replies still work.

## 10. Decided by the controller (to check while reading)

1. The second listener's default port (main port plus one) and `PAP_PREVIEW_ORIGIN` for reverse proxies.
2. Tokens in memory only: a restart revokes every preview link.
3. Services restart nothing by themselves. 4 per box, 200 log lines.
4. A live strip derived from the running services announces a preview. Nothing about it is stored in the transcript.
5. The daemon, never the client, supplies the HTML of an artifact, keyed `(entryId, fenceIndex)`.
6. CORS headers are added on the untrusted origin, and pap refuses `Sec-Fetch-Site: same-site` (§4).
7. `running` needs the port to belong to the service's own processes (§5).
8. Images load only as `<img>`, in six image types, up to 10 MiB (§8).

## 11. Left to the builder

- The guest supervisor's code and how it shares the shell's argv builder.
- The namespace mechanism for services without network, with a proof on the Kata suite.
- The listener's HTTP relay, using Node's `http` and the existing kernel pieces, with no new dependency for the relay.
- How a running service is announced on the existing streams, for example the `launches` or `boxes` stream, or a small `previews` stream.
- Mermaid and KaTeX versions, pinned and older than `minimumReleaseAge`.
