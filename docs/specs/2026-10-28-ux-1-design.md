# UX-1: links, terminal hand-off, quotes, context meter, prompt templates

Status: approved by the owner (decision 138) · Date: 2026-10-28 · Lot UX-1 of the UX review (owner, 2026-10-28: "go pour LOT UX-1 et Lot UX-2 dans des lanes en //"). The owner dropped the plan/todo panel (Pi has no native todo tool; extension widgets already render above the composer).

## 1. Intent

Moving from the chat to the code takes too many steps today. A path the agent names has to be typed again in Files. A shell command it suggests has to be copied into a terminal by hand. Nothing tells the owner how full the context is before a compaction surprises them. A prompt that works has no way to become reusable.

UX-1 removes that friction with four small features, all in the web app plus thin daemon support. Nothing in UX-1 changes what an agent or a session may do: every action is the owner's click, and every write keeps today's rules.

## 2. Goals

- **G1. Paths are links.** A file path in an assistant message opens that file in Files, at the line when one is given.
- **G2. Shell blocks go to the terminal.** A shell code block in an assistant message has a button that types it into the session's terminal. Nothing runs until the owner presses Enter.
- **G3. Quote a passage.** Selecting text in an assistant message offers to quote it in the composer, or to quote it with a request to record it in the project's knowledge.
- **G4. Context and cost at a glance.** The composer shows how full the model's context is and what the session and the current run cost.
- **G5. Save a prompt as a template.** One of your own messages can be saved as a Pi prompt template, which then appears in the `/` menu.

**Non-goals:**
- a plan or todo panel (dropped by the owner);
- running anything without the owner's Enter;
- a pap-only template syntax or a variables form (Pi's own template arguments cover it, *controller's call*);
- recipes that create a project, an agent and a trigger at once;
- project-scoped templates (`.pi/prompts/` of a project);
- links in tool output, in user messages, in fenced untrusted text, or in an extension's text;
- a terminal for agent threads (there is none today).

**Anti-goals:**
- a link that reaches a path the session could not open through Files today;
- a button that runs a command by itself, or that types into another session's terminal;
- a meter that reads as money spent for a subscription (it is API-equivalent);
- a template write that skips the password Pi's folder asks for.

## 3. Constraints

- AGENTS.md rules: 400 lines per file, module boundaries, tokens only, no `[…]` values, erasable TypeScript, every RPC method declares a permission, handlers decode then call one service method.
- DESIGN.md: mono capitals on buttons, 44 px targets under a coarse pointer, labelled tooltips (no `title`), polite live regions, EN and FR (« vous »).
- Bundle: the initial chunk stays under `budgets.json` `initialBundleGzipKb` (300). Everything new lives in the session screen's lazy chunk or deeper.
- Model text stays untrusted: no HTML from it, links built only from what the parser recognises, hidden characters stripped (`stripHidden`) before anything is shown or sent.
- Members: everything works for a member inside their box projects. The template write is owner-only (Pi's folder: `pi:admin`).

## 4. The features

### 4.1 Paths are links (G1)

- **Where.** In assistant message text and inline code spans, after Markdown parsing. Never inside fenced code blocks (copy stays the way to take a block), never in tool output, user messages, `Fence` content, extension text or agent event cards.
- **What counts as a path** *(controller's call; the builder may refine the pattern, keeping the anti-goals)*:
  - a relative path with at least one `/` or a known file extension (`src/app.py`, `README.md`), optionally followed by `:<line>` or `:<line>:<col>`;
  - an absolute path at or under the session's own roots: its folder, its project root, a box project's root (`/boxes/<id>/project/...`), or, in an agent thread, the agent's guest folder `/agent/{home,inbox,knowledge}/...`, which maps to pap's `/agents/<id>/...` (the explorer's mapping, `files.md`);
  - URLs, `~` paths, `..` segments and anything outside those roots stay plain text.
- **No existence probe.** A link renders without asking the daemon whether the file exists (no request per path while a reply streams). A click opens Files; a missing file shows the viewer's existing "not found" state.
- **The click.** Opens (or focuses) the session's Files pane at that path, through the existing item kinds and `files.*` methods; the daemon's file rules decide, as today. With a line, the viewer scrolls to it and marks it (CodeMirror). A box that is stopped shows the existing START panel; a click never starts a box.
- **Look.** An inline text button in the accent colour with an underline on hover and focus; the accessible name says "Open <path> in Files". It wraps like text.

### 4.2 Shell blocks go to the terminal (G2)

- **Which blocks.** Fenced code blocks whose language is `bash`, `sh`, `shell`, `zsh` or `console`, in assistant messages of a session that has a terminal (host projects for the owner, box projects for everyone). Hidden for agent threads, tasks and children.
- **The button.** Beside the existing copy button: "TO TERMINAL" (icon and label). For `console` blocks, a leading `$ ` or `# ` prompt is removed from each line.
- **What it does.**
  - It opens the session's terminal if none runs for that folder, or reuses the newest running one for that folder.
    - The folder is the session's own folder (`surface.ts` `placeOf`).
    - Opening goes through one `terminal.create` and the existing surface rules.
    - As in B2, opening a terminal on a stopped box starts it. That is the owner's explicit click, unlike browsing *(controller's call)*.
  - It opens or focuses the terminal pane and waits for the attach to finish (the `end` of the replay). If the attach has not finished after 10 s, it says so inline and types nothing.
  - It types through xterm's own paste path, which wraps the text in bracketed paste when the shell asked for it. It **never adds a final new line**.
  - Multi-line text is typed only when xterm reports bracketed paste mode on, so the shell holds it until Enter. Otherwise the button types nothing and says, inline, "This shell cannot hold several lines: copy the block instead." *(controller's call)*.
  - Hidden characters are stripped before typing.
- **Invariant.** Nothing runs until the owner presses Enter in the terminal. A test proves it for single-line and multi-line blocks.

### 4.3 Quote a passage (G3)

- **Trigger.** A non-empty text selection inside one assistant message shows a small toolbar.
  - With a fine pointer, it floats above the selection.
  - With a coarse pointer, it is a strip pinned above the composer while the selection lasts, driven by `selectionchange`, so the platform's own selection menu stays usable *(controller's call)*.
- **Actions:**
  - **QUOTE**: inserts the selection into the composer as a Markdown quote (`> ` on each line) followed by an empty line, at the caret. It never sends.
  - **TO KNOWLEDGE** (only when the session's project has OKF, from the existing knowledge chip state): inserts the same quote preceded by one fixed line asking the agent to record it as a concept in the knowledge folder. It never sends, and pap writes nothing itself.
- The selection's text is stripped of hidden characters first. Escape or a click elsewhere closes the toolbar.

### 4.4 Context and cost at a glance (G4)

- **Where.** One quiet line in the composer's model bar, after the model and thinking pills.
- **Context.** `<used> / <window> tokens` and a thin meter, from the model's `contextWindow` (`SessionView.loadout`) and the tokens of the newest assistant message's usage (input plus cache read and write plus output, as Pi counts its context). Hidden when either is unknown, never guessed.
  - At 80 % and above the meter turns to the attention tone and the line adds "compaction soon". The tone is never the only signal: the word is there.
- **Cost.** "Session <cost> · run <cost>" from the daemon's `RunsPort.sessionCost` (finished runs plus the live run, children included) and the open run's live cost. A subscription session says "API-equivalent" next to the figures, as everywhere else.
- **Sources** *(controller's call)*.
  - Context: the usage of the newest assistant message in the loaded transcript, the snapshot's when the session is cold. When no such message exists, or the loadout has no `contextWindow`, the meter hides.
  - Cost: a new, minimal field on the session stream, filled from `RunsPort.sessionCost` and the open run's live cost.
  - Freshness: children's cost refreshes at their status changes, as today. That lag is accepted.
  - Updates ride existing session events, at most once a second. No polling.

### 4.5 Save a prompt as a template (G5)

- **Where.** The actions of one of your own messages (beside Edit and Fork): "SAVE AS TEMPLATE". Owner only (members do not see it).
- **Dialog.**
  - Name: there is no schema for it in contracts today. A new one goes in `@pap/contracts`, used by the dialog and the daemon: lower-case letters, digits and `-`, 1 to 64 characters, starting with a letter or digit. The builder narrows it to Pi's own rules if Pi's are stricter.
  - An optional one-line description, written as Pi's template frontmatter when Pi supports it.
  - The body, prefilled with the message text (editable, 32 KiB at most).
  - Pi's own argument placeholders work in the body. The builder confirms Pi's syntax from Pi's documentation and states it in the dialog's help line.
- **Write.**
  - A new RPC method calls a **new** operation of the Pi configuration helper (ADR 0023; no prompts op exists in `packages/pi-host/src/helper/ops` today). It writes `<Pi agent dir>/prompts/<name>.md`: `O_NOFOLLOW`, a temporary file then a rename, 0600.
  - The method takes the password step-up itself, the way `models.discover` does. It does not go through `files.write`.
  - An existing name answers `conflict`. "Replace" is a second, explicit step that sends `replace: true`.
  - One audit row per write: the name only, never the body.
- **Where it shows.** The `/` menu of new sessions lists it (Pi reads templates at session start; the dialog says it applies from the next session start). For box projects and agents it reaches the box with the next Pi profile image build; the dialog says so in one line.

## 5. Decided by the controller (to check while reading)

1. The path pattern and the roots it accepts (4.1), no existence probe.
2. Multi-line shell blocks need bracketed paste; otherwise the button refuses (4.2).
3. TO KNOWLEDGE only prefills a request; pap writes nothing (4.3).
4. The meter hides rather than guesses (4.4).
5. Templates: global scope only, Pi's syntax, password step-up, owner only (4.5).
