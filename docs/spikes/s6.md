**Verdict: Apache-2.0**, by declared notice and npm metadata, not by SPDX detection. Permissive and not copyleft: pap's own code keeps pap's licence. This is an engineering reading, not legal advice.

If pap redistributes a Derivative Work of the sources (source or built), Apache-2.0 section 4 asks for:
1. a copy of the licence for recipients (upstream ships only the notice, so cite the canonical text as well);
2. a prominent notice on every file we changed;
3. the upstream copyright and attribution notices kept (the files have none; the repo `LICENSE` line is the one to carry);
4. the content of a `NOTICE` file: none exists, nothing to carry.

Also: section 6 gives no right to use the Vercel or "AI Elements" names beyond saying where the code came from; section 3 ends the patent licence if we sue over the Work. pap's own licence is not set in specs A, B, C or D; Apache-2.0 material is compatible with MIT, Apache-2.0, AGPL-3.0 and proprietary releases, not with GPL-2.0-only.

Compliance recipe for M3 (cheap): `THIRD_PARTY_NOTICES.md` at the repo root (Vercel notice, commit, canonical Apache-2.0 text); the five-line header used in `src/Message.tsx` on every derived file; no dependency on the AI Elements packages, so nothing appears in the dependency licence report.

Gaps to carry into M3, not defects of the spike:

- `role="group"` on the branch control has no accessible name (as upstream's `ButtonGroup`).
- Icon-only buttons have a screen-reader label but no tooltip yet (DESIGN 7.1).

## Recommendation for roadmap M3

**Adopt the structure with attribution; do not take the code or the packages.** The licence is clean and permissive, the stack matches (React 19, Tailwind 4, Vite, type-only `ai` imports, no Next.js, no `useChat`), and the Message port shows what a port costs: 79 lines, none copied, about 0.15 h with checks. The value of AI Elements is the component split, the slots and the behaviour details (Reasoning's open and close timing, Question's selection rules), not its markup: every file needs its classes, colours, motion, `className` hook, strings and AI SDK types replaced anyway. Rules for M3:
1. Port with attribution (header on the file, entry in `THIRD_PARTY_NOTICES.md`): Message (done here), Reasoning, InputRequestCard.
2. Use as a reference only, then write from the Pi event model and the pi-web view: ToolCard, ApprovalCard, CheckpointBanner, PromptChips, transcript container.
3. Never use: Composer, Shimmer, anything importing `streamdown`, `motion` or `use-stick-to-bottom`.
4. No dependency on `ai`, `@ai-sdk/*`, `streamdown` or `ai-elements`; no CLI install; add the Collapsible primitive to the M3 primitives.
5. If a licence review rejects a notice-only `LICENSE`, the fallback costs little: nothing in `Message` is copied, and the T3 and pi-web patterns cover the same components.
