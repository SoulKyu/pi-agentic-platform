Le binaire

Version
impeccable --version → 0.1.17+engine ; engine-probe → impeccable-engine 0.1.17. Skill impeccable@4.7.1, dépôt 936867543ac2 (2026-10-23).
Source
Ce que le lanceur skill/scripts/impeccable téléchargerait : https://github.com/pbakaus/impeccable/releases/download/engine-v0.1.17/impeccable-linux-x64 (version lue dans skill/scripts/VERSION), ELF x86-64 statique, 20,8 Mo.
Somme
44c0d601e985980a9c39718fee15b48a8f7cbe67779f6ae05efe9124817ab629 : égale au sidecar impeccable-linux-x64.sha256. confirmé à l'écran
Mécanisme
Le projet publie un sidecar SHA-256 par binaire, produit par .github/workflows/release-engine.yml (actions épinglées par SHA, release immuable, pas de --clobber), et le lanceur refuse un téléchargement sans sidecar ou à somme différente. Limite : le sidecar vient de la même release, il prouve l'intégrité, pas l'auteur. Seul le binaire Windows est signé (Authenticode) ; les bundles de skills ont une signature Ed25519, pas le moteur Linux.
Bac à sable
bwrap --unshare-all (réseau compris), / en lecture seule, /tmp privé, seul S/work inscriptible ; DO_NOT_TRACK=1 et IMPECCABLE_NO_TELEMETRY=1 en plus (la télémétrie est active par défaut). Cible : une copie de apps/web/src, packages/ui/src, DESIGN.md, du dist bâti et des instantanés DOM.
Catalogue
62 règles (31 slop, 31 quality ; 44 warning, 16 advisory, 2 error), les mêmes que v1 a lues.

Le script de page

Fichier
crates/live/assets/detect-antipatterns-browser.js du même commit, 3,1 Mo, SHA-256 62568938…a2656b9, généré par cargo xtask bundle.
Relu
Entièrement, hors blob WASM (186 Ko de JS, 4 570 lignes). Le WASM est instancié depuis l'octet inline (initSync), jamais par fetch ; ses imports ne sont que des sondes DOM (styles calculés, rects, sélecteurs). Seule entrée-sortie : charger les images d'arrière-plan pour échantillonner le contraste, et postMessage en mode extension (non utilisé). Pas de réseau : injecté.
Exécution
window.__IMPECCABLE_CONFIG__ = { autoScan: false }, puis impeccableDetectAsync({ visualContrast: true }) ; une fois impeccableScan() pour la capture de l'overlay. Contexte Playwright bypassCSP: true (la CSP script-src 'self' de pap bloque le WASM) ; WebKit refuse quand même le WASM, la passe téléphone a donc tourné sous Chromium (Pixel 7, 320 px).
Pages
13 desktop (home, approbation, session 1440 et 1024, Appearance, MCP, Models, Automation, GitHub, Tasks, en Night et Day) et 2 téléphone (home et session à 320).

async function shrink(page: Page, png: Buffer): Promise<Buffer> {
  let data = png;
  let factor = Math.sqrt(MAX_BYTES / data.length) * 0.92;
  for (let round = 0; round < 4 && data.length > MAX_BYTES; round++) {
    const scratch = await page.context().newPage();
    try {
      const url = await scratch.evaluate(
        async ({ b64, f }) => {
          const img = new Image();
          img.src = `data:image/png;base64,${b64}`;
          await img.decode();
          const canvas = document.createElement("canvas");
          canvas.width = Math.round(img.width * f);
          canvas.height = Math.round(img.height * f);
          const ctx = canvas.getContext("2d");
          if (!ctx) throw new Error("no 2d context");
          ctx.imageSmoothingQuality = "high";
          ctx.drawImage(img, 0, 0, canvas.width, canvas.height);
          return canvas.toDataURL("image/png");
        },
        { b64: png.toString("base64"), f: factor },
      );
      data = Buffer.from(url.slice(url.indexOf(",") + 1), "base64");
    } finally {
      await scratch.close();
    }
    factor *= 0.85;
  }
  return data;
}
