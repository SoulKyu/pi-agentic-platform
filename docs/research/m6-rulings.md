# M6 rulings (KISS install: git checkout script and offline archive)

Source: `docs/plans/2026-10-15-m6-install.md` (M6R1 to M6R44, with the red-team and owner answers i1 to i6, decision 87). **Where a ruling below and the code differ, the code wins and the difference is listed under "Execution rulings".** Shorthand: "Cost" is the cost if the ruling is wrong.

## Plan rulings

- **M6R1** `pap service` takes no instance lock and never opens `$PAP_HOME`. Why: it must work while the daemon runs (reinstall) and must not create a home as a side effect. Cost: an install on a host with a corrupt home succeeds and the daemon then refuses to boot (journal hint).
- **M6R2** The unit is a fixed template with three allowlisted paths (`--node`, `--main`, `--home`) and one number (`--port`). Why: the whole injection surface is `safePath`. Cost: a path with `%h` or a space reaches systemd.
- **M6R3** Unit environment is `PATH=<node dir>:/usr/local/bin:/usr/bin:/bin` and `PAP_HOME` when given. Hardening is `NoNewPrivileges`, `RestrictSUIDSGID`, `LockPersonality`; never `ProtectHome`, `PrivateTmp`, `RestrictNamespaces`, `PrivateUsers` or a syscall filter without `@mount`/`unshare` (M11's bwrap needs user namespaces). No secret or M11 env in the unit. `StartLimitIntervalSec=120`, `StartLimitBurst=5`. Cost: a stricter unit is a one-line follow-up.
- **M6R4** `TimeoutStopSec` = `ceil(STOP_DEADLINE_MS / 1000) + 10`. Why: systemd must not SIGKILL a daemon still shutting down gracefully. Cost: killed workers, a stale lock (the boot sweep recovers).
- **M6R5** Linger (i2): check with `loginctl show-user`, run `loginctl enable-linger` (15 s cap, a timeout counts as a refusal), re-check, else warn with the exact command and continue. Cost: a service that stops at logout on a VPS.
- **M6R6** Reinstall restarts the running service and says so; sessions and `$PAP_HOME` survive. Cost: a running turn is cut.
- **M6R7** Readiness and the setup URL come from the user journal by `InvocationID`, read by `readJournal`; `is-active` is not readiness. Outcomes: `listening` with URL (print), `listening` without (owner exists), no `listening` after 40 reads (exit 1, hint, no URL). If the invocation match is empty, retry with `--since`. Cost: a wrong field name until measured (see W5-R2).
- **M6R8** Release id `<version>-<sha7>[-dirty]-<UTC yyyymmddHHMM>` matching `[A-Za-z0-9._-]{1,64}`; a dirty tree needs `--allow-dirty`. Cost: none.
- **M6R9** The template is filled with four validated values; the SHA-256 is of the final `.tar.gz`; the installer is the only integrity check and the docs say it protects against corruption and tampering if the script came over a trusted channel, not against a compromised build host. Cost: a reader overestimating it (hence the wording).
- **M6R10** Both installers forward `"$@"` to `pap service install`, so `--port` and `--home` work from the first command. Cost: a mistyped flag is refused late (documented).
- **M6R11** The archive carries the builder's own Node (24.14 to 24.x) and its LICENSE; the build refuses without the license. Why: no download at build time. Cost: a Node linking libraries absent on the target (the glibc check covers the common case).
- **M6R12** `MIN_GLIBC` is the build host's glibc; build on the oldest target. Cost: an archive refused on an older host (visible).
- **M6R13** `safePath` allows `[A-Za-z0-9._+@/-]`, absolute, no `..`, no `//`, at most 1024 characters. Why: systemd splits on whitespace and expands `%`, `$`, `\`; an allowlist is shorter than a correct quoting layer. Cost: a legitimate unusual path is refused (fixable by another `--home`); a looser rule would write an injectable unit.
- **M6R14** `readJournal` accepts a setup URL only with `http:` and host `localhost`, `127.0.0.1` or `[::1]`, takes the last valid line, ignores torn or foreign lines. Why: M6 binds loopback only; a journal line is data. Cost: none (default log level `info` always logs `listening`).
- **M6R15** `install` order: parse and `safePath` every flag, check both files and `node --version`, user manager, linger, write unit then launcher (foreign is a warning), reload, enable, restart, wait for `listening`. Why: cheap refusals first, nothing written before checks. Cost: none.
- **M6R16** The summary is fixed text (unit path, listening address, setup line or owner line, journal sentence, `ssh -L` line, data line, launcher line, restart line). Cost: none.
- **M6R17** `uninstall`: stop, disable, remove the unit and our launcher, reload; never touches `$PAP_HOME` or the releases. Cost: leftover releases (documented).
- **M6R18** `install.sh` checks run before any build: root, Linux, checkout shape, Node, `gcc g++ make python3 systemctl`, user manager, bubblewrap warning, pnpm or corepack. Why: a 5-minute build must not fail at minute 4. Cost: a late failure.
- **M6R19** `install.sh` ends with `exec "$node_bin" ... service install --node ... --main ... "$@"`; never `sudo`, never edits `PATH`. Cost: none.
- **M6R20** Staging recipe: copy manifests, lockfile, workspace file, allowlisted `.npmrc` and four `dist` folders into a stage, `pnpm install --prod --frozen-lockfile --offline --filter @pap/daemon...`, strip builder state. Cost: needs a populated pnpm store (reported with a fixed sentence).
- **M6R21** The builder refuses missing `dist` folders and a dirty tree without `--allow-dirty`. Cost: none.
- **M6R22** Fixed `tar` argument list with `--sort=name --owner=0 --group=0 --numeric-owner --mtime=@<epoch>`; checksum with `node:crypto` over the stream; stage removed in `finally`. Cost: none.
- **M6R23** Node copied after `--version` shows 24.14+; `BUILD_INFO.json` = `{ releaseId, builtAt, node, glibc, gitSha }`. Cost: none.
- **M6R24** Template values match fixed patterns; a failing value aborts before the template is read. Cost: none.
- **M6R25** Archive installer order (full list in M6R38). Cost: see M6R38.
- **M6R26** Releases other than the new and the previous are deleted last, after `service install` succeeded; the same id re-installed keeps the complete folder. Cost: one extra release on disk until the next install.
- **M6R27** The archive installer never reads or writes `~/.pap`. Cost: none.
- **M6R28** The smoke runs the real `pap service install` (temp HOME, fake `systemctl`/`loginctl`/`journalctl`), parses `ExecStart=`/`Environment=` from the written unit and spawns exactly that line (under `setpriv --no-new-privs` when present). Why: it pins the unit text against the real daemon. Cost: none.
- **M6R29** Smoke assertions: `listening` and loopback `setup_url` lines, launcher passes `sh -n`, mode 0755 and forwards `"$@"`, `GET /` answers 200, not reachable on a non-loopback address, SIGTERM ends it with 0, `$PAP_HOME` 0700 and `state.db` 0600. Cost: none.
- **M6R30** The archive method is not smoked in CI (production install, network, minutes); its CI coverage is the builder's and installer's unit tests, its end-to-end proof is the owner check. Cost: a regression in the real archive is found by hand. See W5-R10 note.
- **M6R31** (i1) The two methods are the git-checkout script and the offline archive with a pinned SHA-256; `curl | sh` and OCI go to M6b. Cost: see ADR 0055.
- **M6R32** (i2) The installer enables linger itself and prints the command when polkit refuses. Cost: see M6R5.
- **M6R33** (i3) Reinstall restarts the service and says so. install.md lists what an M11 restart also does: interrupts agent runs, expires pending agent and secret requests, drops "use once" values, marks subagent rows `interrupted`. Cost: surprise on update if unread.
- **M6R34** (i4) glibc is documentation ("build on the oldest host"); the installer refuses an older glibc. A podman wrapper is M6b. Cost: a refused archive.
- **M6R35** (i5) The setup URL is read from the user journal; docs say the one-time token sits in the persistent journal until used, readable by `adm` / `systemd-journal` members and the owner's own processes outside an agent sandbox, with `pap service url` and a 0600 file under `$PAP_HOME` as the fallback to open on a shared host. Cost: token visible to group members until used.
- **M6R36** (i6) `~/.local/bin/pap` launcher, no `PATH` edits; the summary says so when the directory is not on `PATH`. Cost: the owner types the full path.
- **M6R37** Launcher: `<bin-dir>/pap` (default `$HOME/.local/bin`, `--bin-dir` for by-hand tries), fixed text with marker, `PAP_HOME` only with `--home`, atomic write (0755); foreign files and symlinks are never replaced; uninstall removes only ours. Cost: a foreign file means no `pap` command (warned).
- **M6R38** Archive installer order: refuse root, platform, unsafe `HOME` before anything is hashed or written; prerequisites; stale stage removal; one private copy hashed, listed and extracted; incomplete release replaced; `current` switched only after verification and put back when `service install` fails; pruning last. Cost: one extra archive of disk during the install.
- **M6R39** The stage carries an allowlisted `.npmrc` or none; credential scan refuses; `node_modules/.modules.yaml` removed. Cost: none.
- **M6R40** Method 1 resolves the real Node binary with `node -p process.execPath`. Why: a volta/asdf shim's directory would land on the unit's `PATH`. Cost: none.
- **M6R41** The determinism claim is "byte-identical given the same staged tree"; real pnpm output is covered by `--sort=name --mtime`, verified across two runs. Cost: a differing archive hash across builds of the same commit.
- **M6R42** Both installers warn, never install, when bubblewrap is missing or not root-owned; install.md names Ubuntu's AppArmor userns profile and the `systemctl --user edit pap` drop-in for `PAP_BWRAP`. Cost: agents refuse to start until bwrap is installed.
- **M6R43** install.md says the unit's node directory under the home is hidden in M11 sandboxes, so agent shells have no `node` unless installed system-wide. Cost: a surprised agent user.
- **M6R44** Merge order and shared files: M6 merges first (small, no migration, no contract); backups (M6b) treat `secrets/vault/key` separately and promise nothing about M11's copy; the heavy gate takes one `flock` shared with M11's lanes. Cost: a whole-line rebase for M11.

## Execution rulings

- **W5-R1** Keep `StartLimitIntervalSec=120` / `StartLimitBurst=5` instead of `RestartPreventExitStatus=1`. Why: a real crash also exits 1 and must restart a few times; the limit bounds the loop of M6-RT-01; readiness is the `listening` line. Cost: a daemon that cannot bind restarts a few times before systemd gives up.
- **W5-R2** The journal field (`_SYSTEMD_INVOCATION_ID` versus `USER_INVOCATION_ID`) and the worker scope under `NoNewPrivileges` are checked on the real host by the controller (implementers never touch the real user manager). Measured on this host (systemd 259): lines carry `_SYSTEMD_INVOCATION_ID`, no `USER_INVOCATION_ID`; `-u` plus a field match is an AND. Fallback: drop `NoNewPrivileges` alone and note it in ADR 0056. Cost: one hardening directive less. Real-host check: not run before the merge (owner, 2026-10-16). CI, the smoke of the installed unit and the measurements above cover what is proven; a real `pap.service` under `NoNewPrivileges` with a worker scope, linger and the archive on a real host are checked in M6b.
- **W5-R7** `NoNewPrivileges` is M6's call; M11 depends on no unit directive; the owner's preview check (Settings > Agents under the real service) is the proof after both merges. Cost: agents fail under the installed service until the directive is dropped.
- **W5-R8** `UMask=0077` dropped from `pap.service` (supersedes the plan's constraint line and M6R3's mention). Why: the daemon sets 077 for its own home and keeps the starting umask for the owner's terminals, workers and lane scripts (R114/R114b); under the unit that umask would turn owner files 0600. ADR 0056 lists it under "deliberately absent". Cost: `$PAP_HOME` files rely on `prepareHome` alone (already the case under `pap serve`).
- **W5-R10** The archive builder removes pnpm's `.bin` shims (they embedded the builder's home path and broke reproducibility; the runtime never uses them) and node-gyp leftovers beside `pty.node`, and fails closed if a staged file still names the stage path or the builder's home. Cost: a package that execs a sibling through `.bin` at runtime would break (none in pap's production graph). Note: the T6 smoke runs the repo `dist`, not the archive (M6R30); the archive's real proof is the controller's real-host run.
- **T5 hardening** (ADR 0057): `unset TAR_OPTIONS`; `chmod -R u+rwX` then fatal `find` checks of the extracted tree; the listing parsed with numeric owners; prune failures only warn.
