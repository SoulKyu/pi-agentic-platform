# Policy pipeline

Code: worker side `packages/pi-host/src/policy/` (`extension.ts` thin factory, `pipeline.ts`, stages, `trail.ts`, `audit-sink.ts`), `redact-stdio.ts`, `redacting-ipc.ts`; daemon side `modules/policy/` (rules, settings, `session_policy`), `modules/sessions/policy-link.ts`, `modules/audit/`, `cli/`. Contracts: `packages/contracts/src/{policy,policy-methods,pi-host,audit}.ts`. ADRs 0002, 0020, 0021, 0022. Rulings: `docs/research/m5-rulings.md`. Auth, tokens and devices: `auth.md`.

## The pipeline

- `pap-policy` is the last `tool_call` handler (ADR 0002). One evaluation runs the stages in order; the first `block` ends it. Any error, an unknown outcome or an unreadable input blocks (fail closed). Rules arrive in `init` and `policy_update` as `PolicyRules` v2 (`.strict()`: a key the worker does not know makes the rules invalid, and invalid rules block every call and stop the worker so the next prompt starts with fresh ones).
- Stages: 00 exposure (the tool set, recorded in the `session` row), 01 command denylist, 02 egress, 03 approval, 04 run guard, 05 containment (recorded only; the sandbox is M11), 06 redaction, 07 fencing and taint. Stage 03 can ask; 01 and 02 block, they never ask (except lever B below).
- Decision-time re-checks (MQ6): the rules version is compared before a call is let through (at most 3 evaluations, then "policy changed during evaluation"); a call a person answered is not asked again, but stages 01, 02 and the read-only rule run again on the current rules and taint, and a block wins. A mode change with open cards applies to the answer.
- A nested call (`parentToolCallId`, codemode) is judged and audited like any call; the guard counts top-level calls only.

## The matrix (stage 03, `decide.ts`)

| Mode | read | edit | exec / network / external-write | unknown |
| --- | --- | --- | --- | --- |
| read-only | allow | block | block | block |
| supervised | allow | ask | ask | ask |
| auto-accept-edits (default) | allow | allow | ask | ask |
| full-access | allow | allow | allow | allow |

- Overrides, in order: read-only blocks everything but a plain read; a write that needs review (outside the folder, a protected path, a folder too broad) and a protected read (pap's `state.db`, `secrets/`, `backups/`, `pap.lock`, Pi's `auth.json`, other sessions' transcripts) ask in every mode but read-only; a tainted session asks Deny / Allow once for every exfiltration-capable or external call, past any grant. Grants (once, session, always) only skip questions the table itself asks; `unknown` offers no always.
- Full access covers pap's built-in checks only. A shell command in full access is limited by the blocked-command list alone: it can read or delete `$PAP_HOME` and `auth.json`. Settings and the full-access confirmation say so (owner Q1).
- Tool classification (`tool-kind.ts`): by the tool's registered source, never by name. Built-ins by `builtin:<name>`; MCP (`builtin:mcp`): `readOnlyHint === true` is a `read`, else `external-write`; every MCP tool is external whatever its `openWorldHint` (stricter than MQ2: a local stdio server is fenced and taints too); `read_mcp_resource` is a read, external, URL-bearing (with a host list set, a custom scheme such as `fixture://` blocks); extension tools are unknown and external unless `openWorldHint: false`. MCP, codemode and `tool_search` are not wired into the production worker until M7: M5's rules for them are exercised in-process by the security tests.
- Run guard (stage 04, `run-guard.ts`): 5 identical calls in a row (identity = the exact canonical input), 150 calls, 60 turns per run; counters reset at `agent_start`; blocked calls count. A trip asks Deny / Allow once; Allow once restarts the tripped streak; deny blocks; with no UI it blocks. Limit: Pi runs the calls of one assistant message in parallel and its `tool_call` hook ordering is not documented, so a burst in one message can pass a limit by a few calls.

## Command denylist (stage 01)

- Applies to every command-bearing tool (built-in `bash`; any tool with a string `command`) except `powershell`, which gets the owner's patterns only. The built-in preset ("catastrophic commands", on by default) is word-level: recursive `rm` on `/`, `/*`, `~`, `$HOME`; recursive `chmod`/`chown`/`chgrp` on `/`; `mkfs*`, `mke2fs`, `mkswap`; `dd of=/dev/<disk>`; `shred`/`wipefs`/`blkdiscard` on `/dev`; a redirection to a disk; a fork bomb (checked first, on the raw text). Owner patterns are globs (`*`, `?`), anchored on a whole segment, matched by a step-budgeted matcher (never a regex from user input). Neither a mode nor a grant lets a denied command run.
- The reader (`shell-words.ts`, `shell-argv.ts`, `shell-heredoc.ts`) resolves quotes, splits on `; & | ( )` and newlines, reads `$(...)`, backquotes, `bash -c`, `eval` and here-document bodies again, strips wrappers (`sudo`, `env`, `nohup`, `xargs`...), emits redirections as words of their own. Limits: 64 KiB, 1 000 segments, 3 levels, a glob budget per call. Owner patterns fold Unicode blanks and lone surrogates, so a pattern may block a command bash would not run (conservative).
- Lever B (owner): when the reader gives up ("too complex", "too long") or an owner pattern runs out of budget, an interactive session with a UI asks Deny / Allow once (card title: "pap could not check this command...") and no grant can skip it. Built-in hits, owner-pattern hits and the fork bomb still block; a catastrophic shape found by a bounded rough scan of the raw text blocks too. Unattended and read-only sessions block. With an egress host list set, an unreadable command blocks at stage 02 and lever B does nothing. Lever D: `daily-use.corpus.ts` keeps about 50 ordinary commands that must pass without a question in the default mode.
- Documented passes (each has a test row labelled so; the reader is best-effort, M5R18): a variable, substitution or ANSI-C word as the command (`c=rm; $c -rf /`, `$(echo rm) -rf /`, `$'rm'`); aliases and functions defined earlier (including one named `cat` or `tee`), scripts written then run, interpreters (`python3 -c`), output piped to a shell (`printf 'rm -rf /' | sh`), a here-string to a shell, a group, loop or function piped to a shell on a later line, a here-document reaching a shell through `$(...)`; `rm -rf /..`, `/[a-z]*`, brace expansion, `cd / && rm -rf *`, `find / -delete`, `find -exec rm`, `xargs rm`; `env -S`, `taskset <mask>`, `chmod --re=...`, `watch 'cmd'`, `flock -c`, `runuser -u x --`; `tee /dev/sda` and `cp img /dev/sda`; a NUL, zero-width joiner or NBSP spliced into the command word. Here-document bodies for `cat`/`tee` with nothing piped on are data (pass); any other receiver (`python3 - <<EOF`, `psql`, `kubectl apply -f -`) is read as commands, so a long inline script may be "too complex" or match a pattern (a false positive). `rm -f a.txt $(ls -R /)` blocks when the reader gives up. An owner pattern can be skipped by spending the call's glob budget in an earlier segment (the stage asks, it does not match later segments); the fork-bomb check runs outside the step budget (about 0.6 s at 2 MiB).

## Egress (stage 02)

- Off by default (`allowHosts: null`). A list, even empty, restricts: a URL whose host is not on it blocks in every mode (a block, not a question). Patterns: `example.com` itself, `*.example.com` its subdomains, not the apex. Ports and paths are not judged.
- URLs come from every string of a non-built-in tool's input (depth 10, 10 000 strings), from the words of shell commands and from built-in network tools. A space-free string starting with `scheme://` is one URL judged whole, and the URLs inside it (redirect, archive and reader-proxy forms) are judged too, so both hosts must be listed. Refused: credentials, a scheme other than http(s)/ws(s), IP literals, backslashes, control characters. Clients with no judgeable host (`curl wget nc ncat socat ssh sftp ftp telnet dig nslookup host`, `git clone|fetch|pull|push|ls-remote`, `scp`/`rsync` with `host:path`) block with "host not checkable"; curl reroute flags (`--proxy`, `--resolve`...), `/dev/tcp`, git `-c *proxy=`, `-c alias.*` and `--config-env` make the segment uncheckable.
- Residuals (also in Settings › Approvals): any allowed URL in a segment unlocks bare hosts next to it (`curl https://example.com evil.test`); host-only fields (`{host: "evil.test"}`); scheme-relative `//evil.test`; free text such as `see https:evil.test`; clients the list does not name, scripts that reach the network themselves, DNS by any program; proxies from the environment or files (`HTTPS_PROXY`, `export`, `~/.curlrc`, `curl -K`, `wget -e`, `.wgetrc`); a `/dev/tcp` path built by expansion; git aliases, proxies and URL rewrites from config files (`include.path`, `GIT_CONFIG_*`, a saved alias), `git clone -c|--config` after the subcommand, `-c url.<base>.insteadOf=<allowed prefix>`, `http.noProxy`, submodules, `remote update`, `archive --remote`, `lfs`; curl short-option clusters other than `-<letters>x`. False positives: `curl -oxfile`, underscore hosts under `*.`, arguments that look like `/dev/tcp`.

## Redaction (stage 06)

- Secrets (`secrets.ts`): worker environment variables whose name holds a credential word (`TOKEN SECRET PASSWORD PASS APIKEY AUTH COOKIE BEARER JWT`..., plus `PGPASSWORD MYSQL_PWD SSHPASS`) and string values in Pi's `auth.json`, 8 to 4 096 characters, not a path, not digits, minus placeholders (lower-case-only values under 12; `password`, `changeme`, `postgres`...). The set is rebuilt when `auth.json` changes. Matching is exact and linear (first 8 characters indexed).
- Where it applies: the `tool_result` hook (text parts, strings of `structuredContent` and `details`), the audit arguments, every record the worker sends (one wrapper of `ipc.send`, `redacting-ipc.ts`: a record that cannot be checked is dropped, a response fails), the worker's stdout and stderr (`redact-stdio.ts`). Reasons are redacted before they are clipped. Live output edges (`edges.ts`): a head or tail of 4+ characters of a known secret becomes `[SECRET:NAME]`, only when Pi marks the output cut or the string was clipped by the worker, never in identifier fields; a spent edge budget fails the record. A throwing redaction withholds the result.
- Marker restoration (owner MQ4): `[SECRET:NAME]` is restored in the input of Pi's built-in `write` and `edit` only, after the question is answered, with environment-sourced secrets only (never `auth.json` values: stricter than MQ4; an agent cannot write a provider key into a file). Never into bash, MCP or extension inputs. A secret with `"` or `\` written into a JSON file is restored unescaped.
- Limits: object keys are not redacted; a value split across text parts, or across `content` and `structuredContent`, is not matched; base64, URL-encoding, reversal, images and a value written to a file then read by another process are not caught; a secret split across two `message_update` deltas leaks its second part (the accumulated message is redacted whole); Pi persists assistant text and tool-call arguments raw in its session file; Pi writes the full unredacted output of a truncated bash command to `/tmp/pi-bash-*.log` (a `read` of it is redacted); direct `fs.writeSync(fd)` and Node's fatal printer bypass the stdio wrapper, and a secret split across two stdout/stderr writes is not found (worker stderr lines built with `logLineOf` are exact-only); free-text string ends that start with a secret's prefix are not masked, only clipped strings are tail-masked, and a clip at a length not in the gate list escapes (`ui-lines` 512 cut then SGR or surrogate strip, session title 80 plus an ellipsis, compaction summary 65 536).

## Taint and fencing (stage 07, ADR 0020)

- External results reach the model inside `<untrusted source="..." id="<12 hex>">...</untrusted id="<same id>">`; `UNTRUSTED_RULE` is appended to the system prompt. Images and `structuredContent` are not wrapped. `bash` output and files are not external (spec C §5 known limit).
- The worker keeps `{tainted, epoch}` and sends `taint` records; the daemon stores them in `session_policy` (`policy-link.ts`, `markTainted(owner, session, observedEpoch)` raises only when `taint_epoch <= observedEpoch`). Path 2 (a `result` audit entry with `external: true`) raises with no epoch check and is load-bearing: never add one. `policy.clearTaint` bumps the epoch.
- Residuals: a daemon crash between a worker's taint send and its dispatch; a clone taken while the live leaf is null, or after a failed `markTainted` and before the next `agent_end`; insert and inherit are not one transaction; a late result entry after a clear taints again (the owner clears twice).

## Audit (ADR 0022)

- Rows: `call` (stages 01-04, 06 if markers were restored), `result` (only when 06 or 07 acted), `session` (00, 05; tools as `{count, truncated, names}`). Append-only by SQL triggers; a worker's entry is parsed, scrubbed of known token formats, budgeted (600 rows per session per minute, a marker row at the gap), at most 100 invalid rows per session. Details: `daemon.md`.
- Size: about 0.5 KB per call row, so 1 000 tool calls a day is about 180 MB a year. Retention is 12 months; `pap audit prune [--month YYYY-MM] [--dry-run]` removes a whole month older than that, with the daemon stopped (`systemctl --user stop pap-preview` first); the boot line `audit_prunable` says when months are prunable. A row can be purged only by editing the file. There is no per-session volume cap beyond the rate: a hostile session can grow the table by about 10 MB a minute until stopped (a compromised worker can already write files under the same account).

## CLI and tests

- `pap serve | audit prune | user add | passkey reset` (`apps/daemon/src/cli/`): see `daemon.md` and `auth.md`.
- Hostile classes per stage (control and bidi characters, lookalike blanks, oversize, depth, cycles, encodings): `*.hostile.test.ts`, `denylist.variants.test.ts`, `denylist.heredoc.test.ts`, `egress.forms.test.ts`. Exit criteria (spec C §8.1): `apps/daemon/src/security/*.int.test.ts` (fail-closed, taint then exfiltration, forged Origin, traversal, an audit line per stage). No test runs `curl`, `wget` or a destructive command: an exfiltration is `echo exfil`, a blocked command is `pap-test-blocked now` under an owner pattern.
