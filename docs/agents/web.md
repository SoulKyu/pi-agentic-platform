# web — agent notes

Code: `apps/web/src/` and `packages/ui/src/`. Specs: DESIGN.md, spec C §7; ADRs 0010 to 0012.

## Shell (`routes/shell/`, `features/workspace/`)

- The URL names the active item. `PANE_RENDERERS` (`pane-renderers.tsx`) maps an item kind to its screen; only the active tab of a pane is mounted.
- The workspace (tabs, split) persists in `localStorage` as `pap.workspace.v1`; a damaged value is dropped, not repaired.
- Lazy parts go through `lib/lazy.tsx` (`LazyBoundary`, `useRetryableLazy`): `LazyPanel` (drawers, palette, help, theme editor), `LazyMenu` (the rail's account menu and the split header, one shared lazy `@pap/ui/overlays` menu) and `LazyPane` (Settings, the session screen). A chunk that fails to load or a part that throws leaves the shell standing and shows a toast with Reload: `lazy_chunk_failed` for a gone chunk (`isStaleChunk`), `render_failed` with a generic message for anything else. The exceptions are the dev-only gallery (no chunk in production) and the lazy primitives behind `Suspense` in `@pap/ui`. The words come from `useLazyFailureText()`; `lib/` never imports the catalogs.
- The session screen is a lazy chunk (`pane-renderers.tsx`); the project home's composer (`HomePane` → `ProjectHome`) is eager, its body is a lazy chunk. Tests that look for a session pane wait with `vi.waitFor`.
- Phone: `MobileShell` (bottom nav, one pane, sheets) replaces the rail layout under the breakpoint; it is in the initial bundle.

## Appearance (`features/appearance/`)

- Two scopes. Device (`pap.appearance.device.v1`): density, text sizes, motion, chat width, the completion sound; the language is per device too (`pap.locale`). Account (the `settings` module, cached in `pap.appearance.account.v1`): mode, themes, custom themes, fonts, label case, grid, rail position, avatar style, tool detail.
- Fonts (Settings › Appearance › Details). `uiFont` is `manrope`, `system` or `custom:<slug>`; `monoFont` is `jetbrains-mono`, `system` or `custom:<slug>` (`AccountAppearanceFields`; an unreadable value falls back to the default, field by field). A custom choice is a family the daemon downloaded (`fonts.add`, `docs/agents/daemon.md`). `FontsBlock.tsx` is the "Google Fonts" block (a family name, Add, the installed list with Remove, the note that the browser never contacts Google); `fonts-store.ts` holds the installed list (`null` until `fonts.list` answered). `resolveAppearance` (`model.ts`, `fonts.ts`) turns an installed custom choice into `data-font-ui="custom"` and an inline `--font-ui` (or `--font-code`) naming the family, then the system stack; a removed family, or a list not loaded yet, falls back to the default font and the select reads "Font removed". The controller keeps one same-origin `<link rel="stylesheet" href="/fonts/<slug>/font.css">` per family in use (`font-links.ts`). The list and the links live in a lazy chunk (`font-support.ts`) that the controller loads the first time a custom font is chosen, so the initial bundle only carries the resolution (about 0.9 KB gzip). The boot script never replays a custom font (the first paint uses the default); the list is read once the socket is open, and only when a custom font is chosen (`syncAccountAppearance`).
- Account documents sync with compare-and-set (`lib/account-setting.ts`): writes are held until the first load settles, send `baseRevision`, and on `conflict` merge field by field and retry once (R105). A timeout is never re-sent.
- Completion sound (M13R21): off by default, a device-local switch in Settings › Appearance › Reading (`completionSound`). `useAnnouncer` (`features/sessions/announce.ts`) is the one place a screen sees its session go running to idle; it calls `playCompletion` (`completion-sound.ts`, exported by the appearance barrel): one 880 Hz tone of 120 ms through a lazily built `AudioContext`, only while `document.hidden` or the window is unfocused. Browsers keep the context suspended until a gesture: turning the switch on builds and resumes it (`unlockCompletionSound`), and with the setting on the announcer also listens for `pointerdown`, `pointerup`, `click` and `keydown` until the context runs (`unlockOnFirstInteraction`; the reload case, and iOS WebKit unlocks on `click`, `pointerup` and `keydown` only). `playCompletion` returns false, and schedules nothing, while the context is not running. A second call within 120 ms (two panes on one session) is skipped. A cold session and a subagent's end play nothing. No audio asset; the tone is best effort if the browser refuses audio.
- The merge also gets `base`, the last server copy the document adopted or saved. It is the cached copy before the first load, and an empty document when the server has none (so a theme only this cache holds counts as an add; the guarantee is narrow: while the server has no document, such a theme survives only if this device edits its themes before its next load). `customThemes` is merged by theme id against it (`mergeThemes` in `model.ts`, themes compared by content with sorted keys): local adds are appended, local edits replace the server's theme or bring it back, a local delete applies only if the server's copy is still as it was in `base`. So an edit wins over a delete on either device, and a theme added on another device is not lost. Ids are slugs of the name, so two devices that duplicate the same preset collide: the server's theme stays, this device's gets a fresh id (`newThemeId`) and its selected side follows. More than 16 themes after a merge drops the last ones (`parseAccount`); a merge in which this device edited its themes and the list goes over 16 before the cut shows a toast (`appearance.themeNotKept`, `mergeCutsThemes`). `newThemeId` lives in `theme-ids.ts`, apart from `theme-io.ts`, so the eager merge does not pull the theme file code out of the Settings chunk.
- Known limit, carried: the keybindings list (`keybindings-store.ts`, field `rules`) is still one field. A conflict keeps this device's whole list when it changed `rules`, so a rule added on another device since the last sync is lost. It needs the same three-way merge, keyed by (key, command, when) since rules carry no id.
- Boot cache: `apply.ts` writes `pap.appearance.boot`; `boot-script.js` replays it before first paint, accepting only allowlisted attributes and variables with plain values. It is emitted as an external hashed file by `vite/appearance-boot.ts` and linked first in `<head>`, because the CSP forbids inline scripts.
- `parseAccount` reads the stored document field by field: each enum/boolean falls back on its own, `customThemes` keeps valid entries (first duplicate id wins, at most 16 kept, 64 examined), a side whose theme is gone or sits on the wrong base falls back to `night`/`day`. Never reset the whole document for one bad field.
- Mode picks the side (Night / Day / System). Dark side: Night Control, High contrast or a custom night theme. Light side: Day Papier or a custom day theme.
- Token selectors are attribute selectors (`[data-theme="…"]`, `[data-density="…"]`) of equal specificity, so the boot script's attribute always wins over the no-JS fallback. `tokens.css` uses `@theme inline`, not `@theme static` as DESIGN §14 writes: a utility must read `var(--bg)` where it is used, so a `data-theme` on a subtree (gallery frames, the logo's mode) re-themes it. A non-inline theme resolves the variable once on `:root`. Do not "fix" it.
- `deriveTheme` mixes (8, 13, 22, 35, 38, 55, 58 %) are pap's own numbers for DESIGN §13.2. `control-border` and `focus-ring` reach 3:1 on bg and surface; `attn-title` 4.5:1 on the attention tint over the surface (ADR 0012).
- `contrast.ts` and `derive.ts` hold colour math, pinned by tests; the ignore list of `pap/no-raw-colors` in `eslint.config.js` names them with `presets.ts`.

## Commands (`features/commands/`)

- `defaults.ts` holds the command specs (`COMMANDS`) and the default chords (each has `!panelFocus`, Escape also `!overlayOpen`); `registry.ts` only the handlers that mounted components register. The user's rules live per account (`keybindings-store.ts`, `pap.keybindings.v1`) and merge over the defaults in `resolve.ts`.
- `when` keys (`CONTEXT_KEYS`): `editableFocus`, `dialogOpen`, `overlayOpen`, `inlineEditFocus` (focus inside `[data-inline-edit]`), `panelFocus` (focus inside `[data-terminal-input]`), `paletteOpen`, `treeOpen`, `sessionFocus`, `mobile`.
- The dispatcher bails out on a composition (IME `keyCode` 229, `isComposing`), on AltGr, and on a lone modifier. It does not bail out on a reserved chord: only the recorder and the JSON import refuse one (`isReserved`, `RESERVED` in `resolve.ts`, per platform). The recorder stores digits and punctuation by physical key (`event.code`), letters by layout key.
- The editor (`editor/`, lazy) shows conflicts and overlapping clauses; a JSON import that would wipe the bindings is refused.

## i18n (`i18n/`)

- `useT()` in components (re-renders on a locale or catalog change); `t()` only outside React, at the moment of use. Both fall back on the key and warn `message_missing`.
- Eager catalog: `en.ts` / `fr.ts`, merged from `catalog/*.ts`. Every key exists in both languages; a French string equal to the English one needs an `IDENTICAL_IN_FR` entry with a reason.
- Lazy catalog pattern: a chunk's strings live in `catalog/<name>.ts` (`settings-screen.ts`, `gallery.ts`) and are added by `registerCatalog({ en, fr })` at the chunk's evaluation. `MessageKey` reaches them through type-only imports. `lazy-catalog.test.tsx` holds the exempt list: the explicit set of Settings chunk files that may name those keys (every listed file must exist); any other file naming one fails the test, so eager code cannot render a raw key.
- The literal gate (`scripts/literal-coverage.ts`, allowlist `scripts/literal-allowlist.json`, every entry with a reason) refuses UI text outside the catalogs. Server texts (R128): a `notice` event or a `status` cause carries a stable `code` (+ `params`) next to its English text; `codedServerText` (`i18n/server-text.ts`) shows it by code in the session's language, an unknown code shows the English text as sent, and an event with no code (an older daemon) goes through the English patterns. The sentences live in the lazy `catalog/server.ts`, registered by the session screen (`features/sessions/register-server-catalog.ts`); a locale switch re-renders them. An extension's own text (`source: "extension"`) is never translated. Notices by level: a LIVE `info` notice (`notice` event, from an extension or pap) is a `Toast` of 5 s through `features/sessions/notice-toast.ts` (the extension label inside the text; the Toaster keeps the latest 3, so a flood does not pile up); a snapshot never toasts, and `info` is never a line. `warning` and `error` stay as lines above the composer with a dismiss button; a dismissal is kept per session, level and text for the browser session (`useDismissedNotices`), so a reconnect snapshot does not bring the line back.

## Markdown (`packages/ui/src/ai/Markdown.tsx`, `markdown/`)

- react-markdown plus remark-gfm, no raw HTML, safe link protocols only, no images (model text never loads a resource). Code fences use shiki with its JavaScript regex engine (no WebAssembly, CSP unchanged) and the code colours of the tokens.
- The renderer and the highlighter are lazy; a load failure calls `onLoadError`.

## Gates

- Class coverage (`scripts/class-coverage.ts`): every class in `className`, `cn(...)` and constants named `*CLASSES|VARIANTS|SIZES|TONES|STYLE|RING` must compile with the real Tailwind config. Class lists live only there. The literal gate (`scripts/literal-coverage.ts`) still skips `features/sessions/`; class coverage and the compiler gate cover it.
- Compiler gate (`compiler-gate.test.ts`, `compiler-pipeline.int.test.ts`): React Compiler runs over `@pap/ui` and the app. `"use no memo"` is allowed only in `features/home/ProjectHome.tsx` and `features/home/ModeChips.tsx` (first-paint bundle), each with its reason on the line; the gate pins that allowlist.
- `pap/no-native-title`: icon buttons use a labelled tooltip, never `title`. Touch targets: the gallery probe checks classes for 44 px under `pointer: coarse`; it does not measure.
- `build-output.int.test.ts`: no inline script, boot script first, fonts as files, no WebAssembly, no gallery in any prod asset, and the initial size held to `budgets.json`. Markers that must be absent from every initial file: Settings, palette `cmdk-input`, the overlays `data-pap-modal`, the shortcuts help `data-command`, the session screen `"data-failure"`, primitives, shortcuts editor, theme editor, markdown. The chunk that holds zod must load with no eval attempt and must contain the `jitless` switch.

## Bundle

- `@pap/ui` declares `"sideEffects": ["*.css"]` and `@pap/contracts` `"sideEffects": false`. Without it, barrel re-exports pin every re-exported module (and its dependencies) into the initial graph even when unused. Import lazy-only features from their own file, not from a feature `index.ts`.
- The ceiling is `initialBundleGzipKb` in `budgets.json` (250 KB gzip, JS and CSS); `pnpm budgets` prints the measured size and the lazy chunks. Lazy loading stays the rule for the editor, terminal, diff and highlighting, and `build-output.int.test.ts` catches a lazy-only module that lands in the initial closure.
- Biggest initial item after the entry: `settings-*` (zod and the contracts settings schemas). Not reduced (`zod/mini` and a lazy `MobileShell` were left out).

## Sidebar, projects and search (M4)

- Shell store (`stores/shell-store.ts`, `shell-reducer.ts`, `shell-feed.ts`): the one eager source of session lists, fed by the `shell` stream. A snapshot replaces everything and clears pending changes; `session`, `project` and `counts` events update it. Sessions are bounded to the window plus pins and projects to 500 plus the pins (evicting projects with no sessions first).
- Optimistic rule (`features/projects/organise.ts`): one change at a time (`pending.size > 0` answers `busy`; Undo waits up to `UNDO_WAIT_MS`, 2 s). `optimistic(commandId, ...)` shows the change with `applyMark` before the answer; an error rolls back **by identity** (`rollback` restores a session only if the store still holds the exact object the change put there, so a newer stream event is never overwritten); an unknown outcome (`timeout`, `connection_lost`) is never re-sent: the change is dropped from `pending`, the sidebar is freed and `subscriptions.resync("shell", "me")` reads the truth back.
- Subscription `resync(stream, key)` (`runtime/subscriptions.ts`): entries are keyed `${stream}:${key}` (`session:<sessionId>`, `shell:me`; the shell key is a local name, the daemon keys the stream by the caller). It drops the cursor so the next answer is a fresh snapshot; with the socket open it releases the current sub and asks again, otherwise the reconnect asks without a cursor. A key with no listener is ignored. The session screen uses it for stale dialogs, the shell for unknown outcomes.
- `features/projects/` holds the tree: `tree.vm.ts` (pure view-model: pinned, one group per project, snoozed, settled, "Other folders"), `ProjectTree.tsx`, `SessionMenu`, `ProjectMenu`, `SnoozeDialog`, `ArchivedShelf`. The tree is a lazy chunk (`TreeDrawer` on ⌘B, the phone's Lists). The project switcher (`routes/shell/ProjectSwitcher.tsx`, eager; its menu through `LazyMenu`) sets `pap.project.v1`; the effective project (`effectiveProjectId`: the stored id if the store knows it, else "All projects") narrows the tree and the home to that project (pins stay visible) and prefills the new-session folder. `pap.project.v1` is one more per-device key, not per account (M3 final m9): revisit with M5's users.
- ⌘K transcript hits (`features/commands/palette/transcript-search.ts`, `TranscriptHits.tsx`): `search.query` from the palette (lazy), at least 3 characters (`MIN_SEARCH_POINTS`; a leading `>` is a command), snippets turned into `<mark>` from the control markers, never HTML.
- ⌘K group order (`palette/rank.ts` `GROUP_ORDER`, `CommandPalette.tsx` `AFTER_HITS`): open items, Lanes, Sessions, Tasks and triggers, the transcript hits, Settings, then Actions last (agreement 21). `>` still lists Actions alone.
- Tree limits: a project whose sessions are all pinned, snoozed or settled has no heading in the ⌘B tree (those sessions show in their own sections), so it cannot be renamed or moved there; rename it from a heading while it has an active session. "Move down" is relative to the visible order (the projects the tree shows, after the switcher's narrowing): it moves the project one place down among the projects the tree shows (it is the move offered only while the tree is not filtered), so a project with no heading in between is not counted.

## Lazy catalogs and the shared group (M4)

- Lazy catalogs: `catalog/sidebar.ts` (tree, menus, snooze dialog, ⌘K transcript words) is registered by `i18n/register-sidebar.ts`, imported first by every lazy chunk that shows its keys: `ProjectTree`, `SessionMenu`, `ProjectMenu`, `SnoozeDialog`, `CommandPalette` and `SessionScreen`. `catalog/session-screen.ts` (M2's 93 session-screen strings) is registered by `features/sessions/register-session-catalog.ts`, evaluated with `SessionScreen`. Eager code must not name their keys: `lazy-catalog.test.tsx` and `catalog-keys.test.ts` pin it.
- `shared` code-splitting group (`vite.config.ts`, Rolldown `codeSplitting.groups`, `tags: ["$initial"]`, `test: /node_modules|packages\//`): modules already in the initial closure go into one `shared` chunk. Without it Rolldown cut them into several small chunks once a lazy chunk reused them, about 3 to 4 KB gzip of glue. Lazy-only modules are untouched.
- Chord as a prop: lazy projects features cannot import `routes/shell` (features import no other feature, and importing the shortcut hook would pull the registry into the chunk). `usePaletteChord()` (`routes/shell/shortcut.ts`) is called by `TreeDrawer` (a lazy chunk of its own, 0.5 KB, that lives in `routes/shell`) and `MobileShell`, which pass `chord` (a formatted string such as "Ctrl+K", or null when the palette has no chord) to `ProjectTree` and `ArchivedShelf`; null selects the `...NoChord` strings. A new lazy feature that needs a shortcut label receives it the same way.

## The session screen in the shell (P3)

- `AppShell` / `MobileShell` own the only `<main>`; session screens are sections (`data-session-screen`). A transcript groups consecutive rows of one author under one `AuthorGroup`; rows sit in a `max-w-chat` column.
- Boundaries: features import no other feature. The command registry and `useCommand` live in `lib/` (`features/commands` re-exports them); the account's `toolDetail` reaches the screen as a prop from `routes/shell/pane-renderers.tsx` (`SessionPane`). `eslint.config.js` lets `web-root` files import `contracts` (`approval-answer.test.ts` pins `@pap/ui`'s `ApprovalAnswer` to the contracts one).
- Keys: `session.stop` (Escape) and `session.sendOther` (Mod+Shift+Enter) are registered by each `Composer`. Both `when` clauses exclude `panelFocus`, `inlineEditFocus` (a `[data-inline-edit]` ancestor: rename field, extension card, approval card), `overlayOpen` and `dialogOpen` (Escape also `paletteOpen`). With two screens mounted a handler acts on the screen holding the focus; run from the palette it acts on the screen that held it last (`last-screen.ts`), and `runCommand` offers the key to earlier registrations when the latest declines.
- The session header is one row (`SessionScreen`, flex-wrap): name and title, the run status chip, the approval mode chip (`SessionPolicy`, its menu: modes, Clear, always-rules, Manage approvals) and the ⋯ menu (`SessionActions`: Rename, Name it, Compact, Export, Duplicate). Both are `LazyMenu`s. Each renders `display: contents`: its button sits in the row and its panels (rename field, Export warning, the full-access and Clear asks, the rules list, outcomes, errors) take `order-last w-full` rows below it. The asks and Escape handling are unchanged (`data-inline-edit` on the policy wrapper while an ask is open). No back link: tabs, ⌘B and ⌘K navigate (decision 25).
- `ApprovalCard` has a compact form (`collapse` prop, set by `ApprovalCardFor`): the command is always rendered in mono, clamped to two lines when it is long, with a button ("Show all N lines") for the rest; controls, note and answers share one row. Without the prop the whole box shows, as before.
- `session.sendOther` is one-shot: it sends this message with the other streaming behaviour while the agent works and never saves it. Only the Steer / Follow up buttons change the saved choice.
- Model text goes through `Markdown`; raw HTML in it is shown as literal text (never parsed, never dropped). Code is highlighted only after 400 ms without a change, so a streaming fence is not highlighted per delta.
- A polite live region (`data-announcer`) says a run ended (running to idle), a new approval, and the branch a switch landed on.

## Policy and access screens (M5)

- Settings sections are listed in `SETTINGS_SECTIONS` (`features/workspace/model.ts:1`). Every M5 screen and catalog is lazy: `catalog/settings-approvals.ts`, `settings-access.ts` (Settings chunk) and `catalog/session-policy.ts` (session chunk, registered by `register-policy-catalog.ts`).
- Settings › Account & devices ends with the AGPL section 13 line and a "Source code" link (`AccountSection.tsx`, keys `settings.source.*`). The href is `sourceUrl(connection.serverVersion)` from `@pap/contracts`: the tag of a release version, else the repository root; `target="_blank"`, `rel="noopener noreferrer"`. The connection keeps `serverVersion` from the hello frame (null before it). See ADR 0077 and `docs/agents/release.md` (forks).
- Approvals (`features/policy/`): the default mode, blocked commands (lines validated with the contract's `DenyPattern`; the built-in preset switch with "What pap blocks" and "What it cannot catch"), the host list (off sends `null`, on and empty blocks every URL), always rules by project, and the audit viewer. The copy states the limits the owner accepted (full access limits a shell command by the blocked-command list only; the egress residuals). Save sends `baseRevision`; a `conflict` re-reads, a `timeout` re-reads first and is never re-sent (R105). Built-in ids are a hard-coded list (`BUILTIN_IDS`; pi-host is not importable); a pi-host test ties it to the shared list in contracts.
- Audit viewer: rows are text only, clipped (reason 200, arguments 300 code points, `plain()` first), at most 1 000 rows, gap markers drawn apart. Fixtures with bidi or zero-width characters are built with `String.fromCodePoint`.
- Account (`features/auth/`): devices, passkeys, tokens; `withStepUp` retries a `step_up_required` once with the same `commandId` after the password prompt (`StepUp.tsx`; the field is emptied as soon as it is read). Revoking this browser runs the sign-out flow.
- Session policy bar (`SessionPolicy.tsx`): the mode select (full access asks inline first), the dashed external-content chip with Clear (inline ask), the "Manage approvals" link. Tainted cards say "external content" and name the tools that tainted the session with their time (`TaintCauseLine`); when every cause is markable the card offers "Mark as local tool" (`MarkLocal`: confirmation, settings write with the revision, clear this session's taint). A bash card whose command starts with `cd <session folder> && ` shows it without that prefix, with an "in the session folder" badge and a toggle for the full command (`session-cd.ts`, display only: the answer and the audit use the full command). Guard cards add the guard line. Escape in an inline ask cancels the ask only.
- Fenced output (`fence.vm.ts`): see Traps.

## zod and the CSP

- zod probes for `eval` (`new Function("")`) when it builds its first object schema, which the daemon's CSP forbids (R74). `vite.config.ts` aliases `zod` to `csp-safe-zod.ts` in the web build only: it calls `config({ jitless: true })` right after zod evaluates, so every chunk that builds schemas sees it, whatever the chunk order. `main.tsx` still imports the file first. `build-output.int.test.ts` loads the built zod chunk with string evaluation refused and expects zero attempts.

Browser tests of the built app are in `e2e.md` (`pnpm test:e2e`); the unit tests run in happy-dom.

## Traps

- Safari 16.4 floor: no native CSS nesting in shipped CSS, no `light-dark()`, no RegExp `v` flag; `:has()` is allowed.
- IME `keyCode` 229 and AltGr produce false chords: see the dispatcher bail-outs above.
- No native `title` attribute. Colours reach components through token utilities only; no raw colours, no `[…]` arbitrary values.
- A lazy-only component imported through a barrel lands in the initial bundle; `build-output.int.test.ts` catches it.
- Fenced tool output (`features/sessions/fence.vm.ts`): only pap's exact format with a matching 12-hex id is shown in `Fence` ("Untrusted · <source>", text only); anything else stays plain text. The id is not a secret to the web (the page sees the whole text), so a fully forged pair only puts the label "Untrusted · <source>" on content, which is harmless. A complete preview is split like the full output; a clipped preview only loses pap's markers (`stripFenceMarkers`).

## Terminal pane (M8)

- `@pap/ui/terminal` (`TerminalSurface`: xterm 6, fit, WebGL with a DOM fallback) is imported only by `features/terminal/TerminalPane.tsx`; xterm and its CSS live in that lazy chunk. The surface hands the feature a `TerminalScreen` (`write` settles on xterm's callback or on dispose; `reset` runs after queued writes) and reports only its own container's size.
- `use-terminal.ts` holds the logic (`createTerminalController`), testable without React: replay protection (typing and xterm replies are dropped until the attach's `end` is written), a 100 ms resize throttle, the inline close question, and the busy state (attach refused with `capacity`): a retry after a backoff of 0.5 to 8 s when the running count in the terminal store drops, at most 5 times, then a "Try again" button.
- The terminal feature keeps no module-level state. The shell's surface code does: `routes/shell/surface-terminal.ts` holds `recent`, `inFlight` and `unknownOutcome` (one create per click, a retry of an unknown outcome reuses its `requestId`); they reset with the terminal store (sign-out, MC34).
- Close on a terminal shown as a split pane unsplits it and closes the terminal, as Close does for a tab. If the WebGL addon throws at `loadAddon` the surface falls back to the DOM renderer. One probe for a `webgl2` context per page, not per mount.

## Panes and the surface switch (M8)

- Session surfaces: `routes/shell/SurfaceBar.tsx` (desktop) and `SurfaceSwitch.tsx` (phone: Chat / Review / Term) open the item kinds `files`, `changes` (the Review pane) and `terminal` (`features/workspace/model.ts`). `surface.ts` finds a session's project root and folder (`placeOf`); the Terminal button stays disabled until the `terminal` stream has its first snapshot, and one click makes one `create` (a double click makes one terminal). ⌘K lists running terminals (`palette-items.ts`). The panes are lazy chunks (`pane-renderers.tsx`).
- Runtime: `runtime/connection.ts` routes binary frames to the terminal channel; `runtime/terminal-channel.ts` (built once, imported only by the terminal feature) attaches on open and after every reconnect with `after` = the written offset, acks every 64 KiB written and when the write queue empties, numbers input frames from 1 per stream (input over 64 KiB splits on UTF-8 boundaries, `split-utf8.ts`), detaches a hidden page after 5 s and keeps at most one attach in flight per terminal per socket (a stale answer never detaches a stream a newer attach holds, MC31). `runtime/upload.ts` is `POST /upload` and `PUT /files/raw` (`fetch`, the daemon's status mapped to codes; a dropped connection is `interrupted`, a client-side outcome). Stores: `vcs-store` (by root), `terminal-store`, `unsaved-files`.

Code: `apps/web/src/features/boxes/` (`BoxStart`, `BoxStopped`, `BoxFact`, `PhaseChip`, `HostsField`, `ResourceFields`, `box-errors.ts`, `use-project-box`, `use-box-action`), `features/projects/` (`AddProjectDialog`, `ProjectSettings`, `DeleteProjectDialog`, `project-settings.vm.ts`), `stores/box-phase.ts`, catalog `i18n/catalog/boxes.ts`. Backend: `agents-vm.md` ("Project boxes").

- **New project.** The dialog has one field, "Project name", with the hint "Its files live in its own box, not on this machine." and the button Create (`projects.create {name}`). The chip menu, switcher and picker say "New project…". Host projects already added stay listed and usable.
- **Scratch.** The project picker offers Scratch ("An empty project for quick sessions."), created for the user on first pick (`projects.scratch`). It can be renamed; it cannot be deleted while it holds sessions.
- **Box fact.** The project home shows `BOX` and a chip: `STOPPED` (tone `mut`, never red), `STARTING` (`run`) or `RUNNING` (`ok`); the chip is a polite live region. `START` is primary: the control is disabled at once, a spinner shows after 1 s and "Starting the box…" after 3 s. A refused start (`capacity`, `vm_bundle_stale`, `agent_paused`, `sandbox_unavailable`, `disk_low`) shows a three-part text. `PACKAGES CHANGED` (tone `att`) shows when `.pi/project.yaml` asks for other packages than the image. A muted note says the files live only in the box: "push them to keep a copy".
- **Stopped panels.** Files and Changes show an `EmptyState` ("The project's box is stopped. Start it to see its files.") with START; the knowledge row keeps a one-line inline sentence and a small START (ruling R10). They read again when the shell stream turns the project's phase `running` (`useOnBoxRunning`, ruling R3). Browsing never starts a box.
- **Off modes.** Lane and Fan-out are disabled with the muted reason "Not available in a box yet." (no host git probe for a box root); lanes in a box come with lot B3. Terminal is enabled since lot B2 (below).
- **Project settings** (lazy, from the box fact and the sidebar project menu): mono uppercase sections `BOX`, `RESOURCES` (memory, CPUs, disk; tabular figures; the disk only grows; the host ceilings apply), `HOSTS` (the project's list, same field as the agent form), `PACKAGES` (the notice and REBUILD), and the buttons SAVE (`projects.setBox`), `RESTART BOX`, `DELETE PROJECT` (danger; the confirmation counts sessions and triggers, names the 7-day trash and asks for the password step-up; Cancel is never danger).
- **Inbox.** A `box_paused` item (a box paused after 3 crashes in 10 minutes) renders as `BoxPausedRow` with the project name and an "Open project" button; its `refId` is the project id.
- **Not yet.** The stream carries no "project removed" event, so another open client keeps a deleted project until it reloads. The French build notices of the image policy are daemon text, French only.

## Settings › GitHub, GitHub projects and the box terminal (lot B2, ADR 0084)

Code: `apps/web/src/features/github/` (`GithubSettings`, `DeleteAppDialog`, `RepositoryPicker`, `GithubHomeEntry`, `GithubTab`, `PullRow`, `CheckChip`, `CheckLog`, `PushBar`, `PrDialog`, `ProjectGithubSettings`, `CloneNotice`, `github-errors.ts`), `routes/settings/GithubSettings.tsx`, catalog `i18n/catalog/github.ts`. Backend: `agents-vm.md` ("The terminal and GitHub in a box"), `auth.md` ("GitHub callbacks").

- **Settings › GitHub** (after Automation). States: no App (neutral `mut` text and `CREATE THE GITHUB APP`, which navigates this tab to the daemon's own page, `/github/app/new`, and from there to GitHub); App created, permission missing (`OPEN GITHUB`, `RECONNECT`); connected as {login} (`DISCONNECT`, `DELETE THE APP`); reconnect needed (`att`, the authorization expired); callback mismatch (the exact URL to paste in the App's settings on GitHub, from `window.location.origin`). `DELETE THE APP` is `danger`: a confirm dialog, then the password step-up. A link or navigation to GitHub is followed only when its origin is `https://github.com` (`githubUrl`) or the daemon's own page (`createPageUrl`); anything else shows the `github_unavailable` line.
- **New project.** A source switch, Empty or From GitHub. From GitHub shows the repository field (type `owner/name` or pick one of yours; the picker waits 250 ms after the first read) and the buttons `CLONE` and `FORK`. The name defaults to the repository's.
- **Project home** (box projects). A clone notice: `pending` chip while the clone runs (3 s poll), or a crash-tone banner with the reason and `RETRY` (`projects.cloneAgain`), "The project is intact and empty.". For a linked project a GITHUB disclosure (a section of the home, not a tab; ruling R6) holds Pull requests (checks as chips `ok`, `run`, `err`, `mut`, always with a word), Issues and Releases, plus `SEND TO A SESSION` on a failed check's log and on an issue. Text from GitHub is plain text only (never HTML, no links built from it); a log is shown in the `Fence` with `UNTRUSTED · github log`.
- **Changes panel.** `COMMIT AND PUSH` (message) and `OPEN A PULL REQUEST` (title, body, base). For a fork the answer is a real `<a target="_blank" rel="noopener noreferrer">` to GitHub's compare page, with the hint "GitHub opens its compare page: create the pull request there."; the panel never uses `window.open`. Hidden for host projects and unlinked projects.
- **Project settings.** A GITHUB section: link an existing repository (typed or picked), `UNLINK` (danger), and the signing key's state chip (absent `mut`, added `ok`, removing `run`, failed `err`).
- **Terminal.** The Terminal action is enabled for box projects; the tab and the pane header name the project once the `terminal` stream has delivered the view.
