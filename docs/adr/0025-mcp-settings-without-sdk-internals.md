# ADR 0025: MCP settings without SDK internals

Status: accepted (M7, Task 17)

## Context

Settings shows the owner which MCP servers Pi will connect to. Pi reads `<agentDir>/mcp.json` and, in a trusted project, `<project>/.pi/mcp.json`. The SDK exports its validator and loader (`validateMcpServerConfig`, `loadMcpConfig`) only through internals that are not part of its documented surface, and both read files with `fs` directly (no real-path check, no size bound, no FIFO safety), resolve nothing but may be extended to do so. An MCP entry carries command lines, URLs, headers and `env` values that are credentials.

## Decision

- The overview reads files only (M7R82). It starts no process, makes no request and resolves no `${VAR}` or `!command`: those are reported by name (`variables`, `commandFields`).
- pap has its own entry schema (`helper/mcp-entry.ts`) that mirrors the documented `McpServerConfig` (`docs/mcp.md`): known fields typed, unknown fields kept, no import of the SDK's loader or validator. Where the two differ, the overview errs towards `invalid` (names must start with a letter or digit and may not be `constructor` or `prototype`; Pi allows a leading `_` or `-`). Test (a later task) tells the truth about a server.
- Files go through `readPiFile` (Task 6b): the real path must lie inside the agent directory or the home (a dotfiles link anywhere in `$HOME` is followed, M7R146), or, for the project file, inside the session folder's real path. A link out, a dangling link, a FIFO, a non-file or more than 1 MiB is a `problem` and nothing is listed. The text is parsed with `JSON.parse`, as Pi does (no comments, no byte-order mark).
- Nothing literal reaches the browser (M7R83). `env` and `headers` values and `oauth.clientSecret` are never sent: names only. The command line, arguments and URL are masked by `helper/mask.ts`, word by word. An argument holding a space or starting with a quote is a command line (`sh -c "..."`, `Bearer x`), and so is the `command` field: it is split as a POSIX shell splits it (quotes group words and are removed, a backslash escapes the next character) and each word goes through the same rules, so `--header 'X-Api-Key: sk-...'` and a quoted URL are read like top-level arguments; a shown word that holds a space is quoted again. A credential flag (`--token`), a credential header name standing alone (`-H X-Api-Key: abc`, `X-Api-Key:`), `-k` or a scheme word (`Bearer`, `Basic`, `Token`) hides the next word, and a scheme word in that place stays and hides the word after it. `--flag=value`, `NAME=value` and headers (`Name: value`, `Name:value`) with a credential name hide the value; any other flag or pair value is read as an argument of its own (a URL, a header as in `--header=X-Api-Key: abc`, a pair as in `--env=API_KEY=x`, several words), unless the whole word looks like a token, which is then hidden. A URL loses its user information, credential-named query parameters (and `code`, `sig`) and token-like query values and path segments; its fragment is masked in place, its route and encoding kept (`#/cb?code=•••`): the same parameter rule, token-like route pieces, or the whole fragment when it looks like a token. Any single word that looks like a token (24+ URL-safe characters with letters and digits) is hidden. Quoting or values nested more than 8 levels deep are hidden whole. Variables in capitals stay readable. A server name that passes the name rule is shown as it is (it is a key and a tool namespace). Other names (invalid ones) are clipped, and one that is a long token is hidden. A bad entry carries one fixed phrase and nothing of its content.
- Project servers count only while the project's trust decision is `true` (`ProjectTrustStore`; an unreadable store means untrusted). Otherwise they are listed `not-trusted` and change nothing. For a trusted project, a same-name global server is `replaced`, or `overridden` for an entry with only `enabled`, `exposure` or `toolExposure`; the global view then shows the override's effective values.
- A file with more than 200 servers lists none (`too-many-servers`); a view over 400 000 bytes lists none (`too-large`).
- The method is `pi:admin` (MC38): browser sessions only, never a token. No file text is returned, only the masked views above, but masking is heuristic (as for the `models.json` editor, MC33).

## Consequences

- A new SDK field is kept by the schema but not shown until a task adds it to the view.
- An entry Pi accepts can show `invalid` (a name starting with `_`, say); one Pi refuses is `invalid` too, with the reason in a fixed phrase.
- The masking rules are heuristics over words, and these are named residuals, shown to the owner who wrote them: a short secret after a flag or key that is not a credential word (credential names are the shared vocabulary of `credential-words.ts`, MC40 and MC41, matched as substrings of the letters of the identifier: key, token, secret, password, passwd, auth, bearer, credential, cookie, pwd, passphrase, session, signature; the query names `code` and `sig` count by their exact spelling); a secret with no credential name or token shape (a short password in an argument position); a header split into words whose value is several words (`-H X-Api-Key: a b` hides `a` only); a short secret in a fragment route piece, or one cut into short pieces by `/`, `?`, `&` or `=` in a fragment that does not look like a token as a whole; a password containing `#`, `/` or a space inside a URL that does not parse, and a URL whose scheme holds a colon is not read as a URL, so the whole `jdbc:` string is shown as written: the user information and a `?password=` query alike (`jdbc:postgresql://u:p@h/db?password=x`); the shell split knows quotes and backslashes only (`$'...'`, `$(...)` and backquotes are not interpreted), and it applies to an argument with a space even though Pi passes it as one argument, so a lone apostrophe (`it's`) is read as a quote. The shown text is rebuilt, not quoted from the file: quotes are dropped or moved (a word holding a space is shown in single quotes, double when it holds one), a query is re-encoded (`+` shows as `%20`) and a bare host gains a `/`. A token never receives these views (`pi:admin`, MC38).
- The `cwd` check is `projects.covers`, which compares paths as text: a subfolder that is a link to another folder reads that folder's `.pi/mcp.json`. The caller is the owner, and Pi started there would read the same file (same as `models.overview`, M7R50).
