# ADR 0088: previews and the untrusted origin

Status: accepted · Date: 2026-10-29 · Spec: `docs/specs/2026-10-28-ux-2-design.md`, plan `docs/plans/2026-10-28-ux-2.md`. Decisions: 138 and 139 (`docs/research/decisions-log.md`). Lifts the non-goal "embedded browser or preview" of spec A §6, for previews of what an agent serves from its own VM. Builds on 0081, 0083 and 0084. Notes: `docs/agents/agents-vm.md` ("Previews"), `daemon.md`, `web.md` ("Previews and rich replies"), `auth.md`.

## Context

An agent or a box session can write a small web site and cannot show it: the VM shell kills a background job when its command returns, and a shell without network has a loopback of its own. Replies also could not show a diagram, a formula or an image from the box. The owner's example: "build a Python HTTP site that follows my training on it", and see it.

Showing what an agent serves means putting content the model wrote, or that a page the model wrote fetched, in front of the owner's browser, next to a signed-in pap. This ADR records how pap does that, and what it does not claim.

## Decision

- **D1. Spec A §6's non-goal is lifted for previews of what an agent serves from its own VM.** It is not a general browser: no external site, no preview of a host project, a lane or a child, no share link, no protocol but HTTP/1.1 and WebSocket over it.
- **D2. Supervised services.** `preview.start {name, command, port}` and `preview.stop {name}` are platform ops (`PLATFORM_OPS`: callers `agent-thread` and `plain`, a box session only; `whenTainted: "run"`; deadlines 60 s and 10 s). The guest runs the command in bwrap with the session shell's own argv, seccomp and capabilities, and keeps it running after the call. At most 4 per box. The answer never carries an address. A service is `running` only on a port its own process tree owns. The daemon decides the box and the network from its own records, never from the worker (a no-network agent's service starts with network false whatever the call says). A service never keeps a box awake by itself.
- **D3. The untrusted origin.** The daemon serves untrusted content on a second listener (`--preview-port`, `PAP_PREVIEW_PORT`, default the main port plus one; `PAP_PREVIEW_ORIGIN` for reverse proxies). Every path starts with a bearer token: `/p/<token>/` for a service, `/a/<token>/` for an HTML artifact. Tokens are in memory only (a restart revokes them all), minted by the owner's own browser through an RPC with a command id, and a service token is a lease: renewed every 60 s by an open pane, and revoked 5 minutes after the last renewal, at the service's stop or restart, at the box's stop, and when its owner is disabled or deleted. Revoked means new connections are refused; a relay already open (a WebSocket, a streamed answer) is not cut by the revocation itself and ends when the pane closes, the service stops or the box stops. An artifact token dies 1 hour after minting. Caps refuse (`limit_reached`) and never evict. The relay drops `Cookie`, `Authorization`, `Referer` and the client's address before the request reaches the VM, answers only the response headers on an allowlist, and never follows a redirect. The page gets an opaque origin: `sandbox allow-scripts allow-forms allow-downloads`, no `allow-same-origin`, no `allow-popups`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, `nosniff`. CORS is open on that origin (`Access-Control-Allow-Origin: *`, never credentials), because an opaque origin makes the page's own requests cross-origin.
- **D4. The page's CSP is restricted by default (decision 139).** A service without network reaches the preview origin (named, never `'self'`, plus its `ws:` or `wss:` form), `data:` and `blob:`. A networked service's page also reaches the hosts of its session's egress list, mapped from the daemon's records when the link is minted and frozen in it; an IPv6 literal, a loopback name, an address the egress proxy always refuses and a name of pap's own are left out. `form-action`, `base-uri`, the frame, child and worker sources are spelled out. An HTML artifact's CSP gives it no fetch, form or frame target (`default-src 'none'`, `form-action 'none'`, `img-src data:`); a CSP does not stop WebRTC or a DNS lookup.
- **D5. The owner's browser frames it, and the label is pap's.** The app's CSP gains `frame-src <preview origin>` and nothing else. `SandboxedFrame` draws the dashed attention frame and `UNTRUSTED · preview <name>` (or `UNTRUSTED · html from the reply`) outside the iframe, where the page cannot draw over it. There are no popups: OPEN IN A NEW TAB opens `/preview/<box>/<name>` on pap's own origin, a page that frames the preview full-window under the same label; the capability URL never reaches the address bar.
- **D6. pap refuses same-site requests where browsers say so.** SameSite ignores ports, so the preview origin is same-site with pap. Every route and the WebSocket refuse a request whose `Sec-Fetch-Site` is `same-site`, `cross-site` or any value other than `same-origin` and `none`: 403, logged `fetch_site_refused` (one line per `via` every 10 s, never the raw header). The exceptions are a top-level navigation to the app shell, `/hooks/*` and the two GitHub callbacks (a cross-site document navigation). A request without the header keeps today's checks. `GET /github/app/authorize` was removed (it was a cookie GET that started a flow).
- **D7. Plain HTTP to a LAN address (decision 139).** Browsers send Fetch Metadata only to potentially trustworthy origins (`https:`, `localhost`, loopback). With `--host <LAN IP> --insecure-http` none is sent, so D6 never fires, and WebKit sends pap's cookie on the GETs of a framed preview. Previews stay on in that mode. What holds there: the page's CSP (the preview origin and its session's hosts, never pap's), CORS (pap's routes send no CORS headers, so a cross-origin page reads no answer), `Cross-Origin-Resource-Policy: same-origin` on `/files/raw`, the Origin guard (a POST from the page carries `Origin: null`), the WebSocket Origin rule, and a route-table test (`testing/get-routes.ts`, `get-routes.int.test.ts`) that classifies every GET route of the real daemon as side-effect-free, nonce-bound, origin-checked or public, so a GET that changed state without a nonce would fail the build. J19 and J20 prove it in Chromium and WebKit with the page framed in pap's real page. `--insecure-http` still sends tokens in clear text; it is a testing mode. The artifact route's `Sec-Fetch-Dest: iframe` check does not apply there either: the browser sends no `Sec-Fetch-Dest`, so a top-level load is served, with the CSP `sandbox` header still on it.
- **D8. Protocol 4.** `AGENT_VM_PROTOCOL` is 4: a `tunnel` hello role carries one relayed connection, with the flow control of the terminals (1 MiB unacknowledged per direction, 64 KiB frames, cumulative acks), the gateway's `ping` answered before any tunnel frame, and a receiver that cuts a peer past the window plus one frame. A service without network is reached by entering its network namespace with a helper (`nsenter`, `util-linux` in the base image, image salt `pap-base-3`), never by widening it. **Run `sudo pap vm setup` after the update.**
- **D9. Rich replies and the Markdown rule.** The rule "model text never loads a resource" now reads **"never loads a remote resource"**. Markdown images load only for a path inside the session's own roots, through the same-origin raw file route (`HEAD` first), as `<img>` and nothing else, in six types up to 10 MiB; a remote URL stays text. Math (`$…$`, `$$…$$`, KaTeX, `trust: false`) and Mermaid diagrams are lazy chunks. A diagram is drawn by Mermaid (`securityLevel: "strict"`, theme keys locked, HTML labels off) and shown as an `<img>` of a `data:` SVG, never as DOM. Every formula and every diagram sits in a `contain: paint` box, so model text cannot paint over pap's UI. An `html` fence offers PREVIEW: the daemon reads the fence itself from the transcript by `(entryId, fenceIndex)`, never from the client, and serves it as an artifact.
- **D10. Service logs are redacted by the daemon.** The guest holds no vault, so it keeps raw lines (200 of 512 characters per service). The daemon masks them with the owner's secrets at each `previews.logs`, before any reader sees them; a redactor that fails answers `internal` and no line (decision 139 addendum, PF-7). Same trust as the mirrors: the lines reach the daemon before they are masked.
- **D11. Platform op and stage 02.** `preview_start` carries a `command`. Stage 02 of the approval pipeline blocks any call with a string `command` in a sandbox-required profile unless it is pap's bash, so the call needed an exemption. It is one predicate, `runsACommand` (`packages/pi-host/src/policy/preview-start-plan.ts`), over a typed set of the ops whose command runs in the guest's own bwrap (today `preview.start`), used by both the category judgement and stage 02. Any other tool or platform op that carries a `command` is still judged. The call is an `edit` for the matrix: read-only blocks it, supervised and the read-only preset ask Deny / Allow once (never a grant), auto-accept-edits and full-access let it run. The daemon re-reads the mode and refuses a read-only session.

## Refusals kept

No automatic start of a service at box start. No preview of a host project, lane, isolated task or child. No remote image, no remote font. No `allow-popups`, no `allow-same-origin`. No cookie, `Authorization` header or `Referer` to the VM. No capability token in a log, an audit row or a receipt (`previews.open` and `previews.artifact` are `secretResult`; logs carry `t:<12 hex>`). No claim in the product copy that a preview is "isolated" or "safe".

## Known limits (never overstated)

What a preview page can still do, and what no CSP stops:

- A page can open a WebRTC connection or cause a DNS lookup. `X-DNS-Prefetch-Control: off` covers Chromium's prefetch only.
- A host name on a networked session's list that resolves, in the owner's browser, to a loopback or LAN address (DNS rebinding) is beyond a CSP: it names hosts, not the addresses behind them.
- A networked service's page can load from and send to the hosts its session may reach, as that list was when the owner opened the preview.
- A page may start a download (`allow-downloads`). The plan fix saw none leave without a click in three engines, which is not a promise.
- A framed page can navigate itself within the preview origin (pap's `frame-src` and the sandbox, which has no `allow-top-navigation` or `allow-popups`, hold it there). Loaded top-level, a sandboxed document may navigate anywhere, so the listener refuses a service request whose `Sec-Fetch-Dest` is `document` (404 `dest_refused`, as for artifacts). In `--insecure-http` LAN mode no `Sec-Fetch-Dest` is sent, so a service URL opened top-level by hand is served and can navigate anywhere.
- A networked service's port check has a millisecond window between the check and the connection.
- A CDN outside the session's host list does not load. Logins by cookie or `Authorization` header do not work in a preview, and an app needs relative URLs (`X-Forwarded-Prefix` helps frameworks that read it).
- In `--insecure-http` LAN mode the `Sec-Fetch-Site` refusal does not apply and WebKit sends pap's cookie on a framed preview's GETs; the layers of D7 hold it off.
- An IPv6-literal app origin cannot frame previews (CSP has no IPv6 source), and an IPv6 host of the egress list is left out of a page's CSP.

Bounds that can be filled:

- The listener's global cap of 256 sockets can be held by an unauthenticated client that re-opens stalled handshakes every 10 s. It concerns the preview listener only (a LAN or loopback port); pap's main origin is unaffected.
- The artifact memory bound is about 64 MiB in the worst case (128 artifacts of 256 KiB as two-byte strings), and the global 128-artifact cap can be filled, by four users, for an hour. An artifact stays viewable up to 1 hour after its session is deleted.

Lifecycle:

- A box stop with a hung or hard-killed guest leaves its tunnels until the peer's FIN or the gateway's ping timeout (about 60 s), as terminals do.
- A network turned off in a thread after it opened leaves a running service networked until it is stopped; the service keeps the network its shell had when it started.
- A stopped box needs START, then START PREVIEW again. A service never restarts itself.

Rich replies:

- KaTeX's `maxSize` does not cap negative sizes: `\raisebox{-15em}{x}` and `\kern-30em` get through, and sizes built by macros add up. The guarantee is the `contain: paint` box, proven in a browser (J18, Chromium and WebKit), not `maxSize`.
- The image lookup is a `HEAD` and then the `<img>`'s own `GET`: a file can change between them. The daemon caps an inline image at 20 MiB (`MAX_INLINE_BYTES`), whatever the `HEAD` said.
- A price before a formula (`$5 … $x$`) leaves the formula as source. A fence inside a list or a quote gets no PREVIEW.
- Mermaid's image shape `A@{img: …}` makes a credentialed same-origin `GET` from the owner's browser, and an image that cannot be decoded can stall Mermaid's queue. A diagram is an image, so its links do not open.
- Offline, the first diagram or formula needs the network: the Mermaid and KaTeX chunks and fonts are not in the service worker's precache.

## Consequences

- A new listener, a new port to expose: a LAN or reverse-proxy setup must forward it (`install.md`), and `pap doctor` checks it (`preview.listener`). If it cannot bind, pap runs on without previews (`preview_listener_unavailable`, `previews.open` answers `unavailable`).
- pap-vmd does not change; the guest bundle and the base image do: run `sudo pap vm setup` after the update.
- The Preview entry of the tab bar and the phone switch is in the shell; the strip, the pane, the logs dialog, Mermaid, KaTeX and the artifact frame are lazy chunks.
