# ADR 0069: the provider form writes models.json, field-preserving and strict

Status: accepted (models batch, chain B)
Date: 2026-10-17
Spec: M7 (Settings › Models). ADR 0023 (Pi's configuration is read and written in a helper), ADR 0026 (`models.json` writes), ADR 0068 (one source for the models a context may use). Rulings: MPR8 to MPR15, MPR20, MPR24, MPR28, MPR-C1, MPR-C3, MPR-C4, MPR-C5 in `docs/research/models-batch-rulings.md`.

## Decision

Settings › Models gets a form that adds, edits and removes one provider of `models.json`: preset cards first (Ollama, LM Studio, vLLM, OpenRouter and three compatible APIs, or custom), then one short form (name or id, API type, base URL, key or auth, headers, models by hand or by discovery). It writes through three helper ops, `models.provider.get`, `save` and `remove` (`packages/pi-host/src/helper/ops/models-provider.ts`), and three daemon methods of the same names. There is no second store: the file is the truth, the raw editor stays.

- **Callers.** `pi:admin`, so a token is `forbidden`. `save` and `remove` take the password step-up; `get` does not. Audit rows `provider_saved {provider}` and `provider_removed {provider}`, ids only (clipped, non-ASCII escaped).
- **Field-preserving merge.** `providers[id]` is edited and every key of the entry the form does not own is kept, so is every unowned key of each model (`compat`, `modelOverrides`, `cost`; models match by `id`). Other providers are untouched. A provider whose entry holds such fields opens with `advanced: true` and the form says they are kept.
- **Strict JSON only (the comments ruling).** Pi accepts `//` comments and trailing commas in `models.json`. A rewrite would drop them, so the form never rewrites such a file: `get` answers `editable: false, reason: "needs_raw_editor"` for every id, `save` and `remove` answer `config_invalid` with the single path `$.file`, and the UI points to the raw editor. An integer of 16 or more digits (a fraction too: the check is a digit run) and a non-finite number are refused the same way. The alternative "rewrite without comments" was rejected: it is a destructive path for an annotated file that the raw editor already preserves. Output is `JSON.stringify(root, null, 2)` plus a newline, so formatting may change; the content does not (an integer-like provider id such as `"123"` moves ahead of the others in object order, as JavaScript orders keys).
- **Write path.** The `baseRevision` of a save is the revision `get` returned when the form opened, never a fresh read at save time, so a change made meanwhile is a `conflict` and the form reloads (MP-RT-03). The HMAC revision is checked inside the daemon's one Pi write queue and again right before the write; Pi's own loader validates the result on a private copy (`save` only: `remove` must work for the odd provider that Pi rejects, MP-RT-02); `writePiFile` writes a 0600 temp file and renames it, a hard link is refused; the `enabledModels` resync follows (ADR 0026). A candidate over 900 000 bytes is refused. `save` carries `id` and `mode` at the top level and lists `sensitiveParams: ["id","mode","baseRevision"]`, so a replay with the same command id and another target is `bad_request`.
- **`get` degrades, never throws.** The form's own schema runs over what was read. A provider outside its grammar (a LAN `http:` URL, an unknown API, an uppercase id, an odd header name) answers `editable: false` with a reason (`not_in_file`, `builtin`, `api_unsupported`, `url_unsupported`, `needs_raw_editor`) and can still be removed. Every literal header value comes back as `keep` (MPR-C3); while a header is `keep` its name is locked (MPR-C4).
- **Base URL policy.** `https:` to any host, or `http:` to this machine only (`localhost`, `127.0.0.0/8`, `[::1]`); no credentials, query or fragment; at most 2048 characters. It is one named constant, `HTTP_PLAINTEXT_POLICY` (`"loopback" | "any"`, `packages/contracts/src/base-url.ts`), and one table of cases, `BASE_URL_TABLE` (`base-url-table.ts`) with a verdict per policy. Flipping to `"any"` is that line plus the two sentences of the `settings-providers` catalog (the policy text and the clear-text warning); no test changes. This is the owner's choice (q4); the red-team (MP-RT-04) argued for `http:` to any host with a warning. The trade-off, stated: **the raw editor is the less guarded door.** It accepts any URL Pi accepts, behind the same step-up, so the loopback rule is a speed bump toward a less guarded editor and not a barrier, and the usual self-hosted case (Ollama on a GPU box or a NAS on the LAN) goes through the raw editor.
- **Keys.** The form has no key field. A `stored` provider writes no key into `models.json`; after the save the UI offers the existing `ApiKeyForm` (`models.setApiKey`, step-up, `auth.json`). An environment variable is `"$NAME"` in the file. A keyless local server gets the dummy literal `local-no-key`, which Pi needs to count it available; it is not a secret. The form never writes a `!command`. A header named like a credential takes an environment reference only; a literal header value is printable ASCII, never starts with `!` and never holds `$` (Pi interpolates `$X` in a literal).
- **Precedence: a stored key wins.** Pi uses a credential stored in `auth.json` before the `apiKey` of `models.json` (probed on Pi 1.1.0 against `$NAME`, `local-no-key` and an absent `apiKey`). The form therefore cannot make "environment variable" or "no key" take effect over a stored key, and it does not delete one behind the owner's back: the edit form says so and points to Sign out. `models.provider.get` reports `keyStored` for the edited id and, with no id, the ids `auth.json` holds a credential for (read through the helper's own store, nothing resolved, no value), so the add form warns before a re-created provider sends an old key to a new base URL.
- **`$NAME` can name any variable of the helper's environment.** An `apiKey` or header reference to `$NAME`, plus a changed `baseUrl`, can send that variable of the helper's environment to a chosen host. It needs the browser session and the step-up, and the raw editor allows the same, so the form adds no capability (MPR28). Refusing names such as `PAP_*` was considered and not done for that reason.
- **Remove.** `remove` deletes the provider entry only. The stored key goes only when the owner ticks it, in the same queue slot (`alsoRemoveKey`: remove, then `auth.logout`). A log-out that answers `not_found` (no key was stored) counts as "no key": the removal stands and no sign-out is audited. If the log-out fails otherwise after the entry is gone, the UI reloads with `get` and, on `not_in_file`, offers "Remove the stored key" through `models.logout` (MPR-C5). `enabledModels` patterns are left; the availability view offers Clean up (ADR 0070). A built-in provider id cannot be created, edited or removed by the form (MPR13).
- **Discover and Test.** The provider host is the owner's own and may be private, so there is no DNS guard (unlike M12 push, whose endpoints a browser chooses). Browser session only, discover behind the step-up, 15 s, no redirect, no cookie, a status class and never a body (MPR15, M7R66). The form imports discovered ids into its draft (at most 500 in all) and saves nothing by itself.
- **Caps.** 300 providers in the file, 500 models per provider, 8 headers, 128 characters of name, 256 of model id and name (MPR20); a create at the cap is refused, nothing is evicted.

## Alternatives rejected

- **Rewrite a commented file without its comments.** Destructive and silent.
- **A key field in the form.** It would hold a secret in a component that also reports errors and keeps drafts (MP-RT-10); `ApiKeyForm` is already tested and empties itself.
- **`http:` to any host with a warning (the red-team's default).** The owner chose loopback; the flip is prepared.
- **A server-side membership check on save** of agents and lanes that name a model: out of scope, a follow-up.

## Consequences

- The residuals are in `docs/agents/models.md` ("Provider form"): commented files need the raw editor, a LAN server needs it under the loopback policy, a strict-JSON rewrite may change formatting, providers, the selection and keys are not restored by M6b (MPR29), the credential vocabulary shared with the maskers has gaps (`X-Pass`, `JWT`).
- The form is a lazy chunk (about 15 KB gzip); the eager bundle grows by the list buttons only.
